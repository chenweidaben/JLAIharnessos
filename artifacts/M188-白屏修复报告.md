## 二、根因分析

### 根因 1（批量，影响 ~150 页）：前端请求 URL 双重前缀

`web/src/services/request.ts` 的 axios 实例 `baseURL = '/api/v1'`。
历史报表页在 `get()` 里又写了完整路径 `/api/v1/xxx`，拼接后变成
`/api/v1/api/v1/xxx` → BFF 返回 404 → 页面进入错误态 / 空态 → 白屏。

**修法**：在请求拦截器里统一剥离重复的 `/api/v1` 前缀（一处修改，全局生效，不改业务代码）。

```ts
// v5.0试点扩展（M188白屏修复）：历史页面误把完整路径 '/api/v1/xxx' 传给 get()，
// 与 baseURL '/api/v1' 拼接后变成 '/api/v1/api/v1/xxx' → 404 白屏。
if (config.url && !/^https?:\/\//i.test(config.url)) {
  config.url = config.url.replace(/^\/api\/v1(?=\/|$)/, '');
}
```

### 根因 2（单页）：TS 接口与 BFF 实际返回形状不一致，强读 undefined 字段崩溃

- `/admin/clinical-research`：页面强读 `data.trials.active`，但 BFF `/admin/research/report`
  实际返回 `projects / papers / achievements / personnel / platforms`，
  触发 `Cannot read properties of undefined (reading 'active')` → ErrorBoundary 白屏。
- `/emr/grade5`：`data.suggestions` / `data.benchmark` 在字段缺失时被 antd List/Table
  读 `.length` 崩溃 → ErrorBoundary 白屏。

**修法**：TS 接口改为宽松可选字段，读取处 `?? {}` / `?? []` 兜底，catch 错误不再 rethrow。
