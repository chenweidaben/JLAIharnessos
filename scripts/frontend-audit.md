## 二、发现的问题（按严重程度排序）

### P2-中：同一路由 path 注册了两个不同组件（后者永远不可达）

React Router v6 对完全相同的 path 按声明顺序匹配，**先声明的胜出，后声明的组件永远渲染不到**。这不是白屏，但会导致「预期进某 V2 页却进了另一个页面」的功能错位：

| path | 先声明（生效） | 后声明（被遮蔽 / 死路由） | 位置 |
|---|---|---|---|
| `emergency/report-v2` | `<EmergencyV2 />`（L3853） | `<EmergencyMgmtV2 />`（L3877，M225-C 急诊管理 V2） | 同一受信布局下 |
| `emr/grade5` | `<Grade5AssessmentPage />`（L3506，带 `emr_level5:view` 权限守卫） | `<EMRGrade5V2 />`（L3571，M187-C，无守卫） | 同一受信布局下 |

建议：确认哪一个是 intended 页面，删除另一个，或给后者改一个不同的 path。

### P3-低：path 重复但指向同一组件（无害冗余）

| path | 两处声明 | 说明 |
|---|---|---|
| `patient-safety-v3/report` | L3997 与 L4117，均 `<PatientSafetyV3 />` | 完全重复，建议删一处 |
| `nursing/nqi-dashboard` | L3533 与 L6599，均 `<NqiDashboardPage />` | 完全重复，建议删一处 |
| `patients` | L3385 桌面端 `<PatientList />`；L7474 `<MobilePatients />` | **不冲突**：后者位于 `/m` 移动端父路由下，绝对路径为 `/m/patients` |

### P3-低：`outpatientRoutes.tsx` 是死代码（未被主路由引入）

- `web/src/router/outpatientRoutes.tsx` 定义了 `/outpatient` 与 `/outpatient/consult/:encounterId` 两条路由，文件头注释写明「供主路由合并」，但**主路由 `index.tsx` 并未 import 它**（全文检索 `outpatientRoutes` 零命中）。
- 实际生效的是 `index.tsx` L6719–6720 自行声明的同名路由（同样指向 `@/pages/OutpatientPage`、`@/pages/OutpatientConsultPage`，文件均存在）。
- 影响：用户从菜单点「门诊问诊」（`/outpatient`）可正常打开，无白屏；但以后若只改 `outpatientRoutes.tsx`，页面**不会有任何变化**，属维护陷阱。建议删除该文件，或在主路由中真正引入它。
