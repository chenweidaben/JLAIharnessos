## P0 级（安全漏洞，阻断性）

### P0-1：JWT 不验签，任意 Token 即 admin

| 项 | 内容 |
|----|------|
| 根因 | `src/bff/middleware/auth.ts` 的 `attachUser()` 仅检查 token 非空，直接赋予 `MOCK_USER(roles:['admin'])`，无任何签名验证 |
| 风险 | 攻击者构造任意字符串作为 Bearer Token 即可获得 admin 权限访问全部 API |
| 修复 | 重写 auth.ts：实现 HMAC-SHA256 JWT 签发（signJwt）与验签（verifyJwt），校验 exp/签名/时序安全比较；开发态仅接受 jt-/jr- 前缀演示 token，生产环境一律拒绝 |
| 验证 | 伪造 token → 401 ✓；篡改签名 → 401 ✓；合法 JWT → 200 ✓ |
| 涉及文件 | `src/bff/middleware/auth.ts`、`src/bff/routes/auth.ts`（登录路由改用 signJwt 签发真实 token） |

### P0-2：错误信息泄露内部细节

| 项 | 内容 |
|----|------|
| 根因 | `withErrorHandler` 将 `e.message` 直接返回客户端，可能泄露 SQL 错误、文件路径、堆栈 |
| 风险 | 信息泄露，辅助攻击者了解系统内部结构 |
| 修复 | 5xx 统一返回"服务器内部错误，请联系管理员"+ traceId，原始错误仅服务端 console.error |
| 验证 | 故意触发异常仅返回通用文案 ✓ |
| 涉及文件 | `src/bff/middleware/error.ts` |

## P1 级（安全加固）

### P1-1：WebSocket 无鉴权

| 项 | 内容 |
|----|------|
| 根因 | `/ws/chat` 升级前未校验 Token，任何客户端可连接接收告警推送 |
| 修复 | 新增 `wsAuthorized()`，校验 query 参数 `?token=` 的 JWT 有效性；未授权返回 401 |
| 验证 | 无 token 连接 → 401 ✓；合法 JWT → 升级成功 ✓ |
| 涉及文件 | `src/bff/server.ts` |

### P1-2：缺少安全响应头

| 项 | 内容 |
|----|------|
| 根因 | 无 CSP/X-Frame-Options/HSTS 等安全头 |
| 修复 | 新增 `securityHeaders.ts` 中间件，统一附加：X-Content-Type-Options、X-Frame-Options:DENY、Referrer-Policy、CSP、HSTS（HTTPS下） |
| 验证 | 响应头全部存在 ✓ |
| 涉及文件 | `src/bff/middleware/securityHeaders.ts`（新增）、`src/bff/server.ts` |

### P1-3：缺少 CSRF 防护

| 项 | 内容 |
|----|------|
| 根因 | 状态变更请求无 Token 校验 |
| 修复 | 新增 `csrf.ts` 双重提交 Cookie 模式：登录下发 csrf-token cookie，POST/PUT/DELETE 校验 X-CSRF-Token 头与 cookie 一致；GET 不校验；Bearer Token 模式下天然免疫，本中间件为纵深防御 |
| 验证 | 有 cookie 时校验通过/失败逻辑正确 ✓ |
| 涉及文件 | `src/bff/middleware/csrf.ts`（新增）、`src/bff/server.ts` |

### P1-4：/system/monitor 无角色控制

| 项 | 内容 |
|----|------|
| 根因 | 任何登录用户可查看系统运行指标（CPU/内存/连接数） |
| 修复 | 增加 `requireRole(c, 'admin')` 守卫 |
| 验证 | 非 admin → 403 ✓ |
| 涉及文件 | `src/bff/routes/system.ts` |
