## 二、Tenant / Campus 模型

- 单节点 `Tenant` 携带 `level: 'hospital' | 'campus'`：
  - `hospital`：`parentId` 为空，代表独立医院租户；
  - `campus`：`parentId` 必指向某 `hospital`，代表该院院区。
- 字段：`id / name / level / parentId / enabled / config: Record<string,unknown> / createdAt / updatedAt? / deletedAt?`。
- **软删除**：标记 `deletedAt` 并强制 `enabled=false`；删除医院级联软删院区。
- **默认保护**：`DEFAULT_TENANT_ID` 指向的默认医院不可停用、不可删除（防锁死）。
- **租户级 config**：键值对，浅合并，禁止存密钥。

## 三、TenantContext 解析来源

优先级：
1. HTTP 头 `X-Tenant-Id` / `X-Campus-Id`；
2. 预留 JWT `tenant` / `campus` 声明（当前 `JwtPayload` 尚未扩展，留待接线）；
3. 均缺省 → 回退 `DEFAULT_TENANT_ID` / `DEFAULT_CAMPUS_ID`。

行为：
- `MULTI_TENANT_ENABLED=false` → 强制默认租户（单院部署透明）；
- 未知/停用/已删除租户 → `MedicalAgentError`（中间件转 403）；
- 指定院区校验 `campus.parentId === tenant.id`，跨院区越权拒绝。

## 四、DataScopeGuard 谓词策略

- **必带** `tenantId` 谓词；
- **仅当上下文指定校区**才叠加 `campusId` 谓词（未指定=全院区视图）；
- **fail-closed**：行无 `tenantId` 不可见；指定校区后无 `campusId` 标记的数据不泄露；
- `assertRowInScope` 用于写操作前的归属断言。

## 七、与技能 / 权限 overlay 的衔接建议

- **技能覆盖**：`skills/registry.ts` 已有 `tenantId` 维度 `TenantOverride`；后续技能加载处注入 `ctx.tenantId` 即可实现「某医院启停某技能」。
- **权限 overlay**：`PermissionConfigStore` 当前按 `module:action` 覆盖；后续可扩展为 `(tenantId, module, action)` 三元键，实现「某医院独立权限矩阵」。
- **科室/病区下钻**：本模块到「院区」一层，科室/病区由 `DataScopeGuard` 在上层继续叠加 `deptId`（复用 `security/types` 的 `DataScope`）。
