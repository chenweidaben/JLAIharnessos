## 一、为什么是"AI 原生"，而不是"AI 外挂"

传统医院信息化的路径是：先上 HIS/EMR 事务系统，多年后再外挂一个 CDSS、一个影像 AI、一个报表 BI。结果是——**系统越用越旧，数据越沉越死，经验随人走而流失**。

JLMEDAIOS 走相反的路：

| 维度 | 传统"事务系统 + AI 外挂" | JLMEDAIOS "AI 原生" |
|---|---|---|
| AI 的位置 | 事后插件、独立孤岛 | 横切每个业务环节的核心引擎 MEDMUSE |
| 数据 | 记录业务结果，用完即沉淀 | 每次操作即学习样本，越用资产越厚 |
| 经验 | 存在医生脑子里，人走经验走 | 沉淀在岗位 Personal Agent 上，可传承 |
| 能力成长 | 靠版本升级，一次升级一次跳跃 | 随日常使用连续进化，平滑成长 |
| 系统形态 | HIS/EMR/药房/质控各自为政 | 业务/数据/AI 三中台一体化 |

**核心结论**：AI 原生医院操作系统的本质，是让医院成为一个会自我学习、自我强化的有机体——**后继者站在巨人的肩膀上，医院原生成长、越来越强**。

### 2.1 业务中台 —— HIS/EMR 一体化，不做信息孤岛
- **HIS**：挂号候诊、门诊/住院工作站、ADT 入出转、床位病区、收费结算、账单、多租户一院多区。
- **EMR**：入院/病程/出院小结/病案首页/知情同意，三级签名，内涵质控状态机，EMR 五级评审自评，智能病历草稿。
- 护理、药房药事、手术麻醉、质控、医保 DRG/DIP、互联网医院共享同一套 **用户、权限、主数据、临床数据模型**，从根上消灭"系统对不上"。
- 并发安全：关键写操作用 **状态机 + 行锁 + 幂等键**，杜绝重复收费、重复发药、重复手术排程。

### 2.2 数据中台 —— 数据原生，操作即资产
- **EMPI**：患者主索引，跨院/跨系统同一人归并。
- **湖仓分层 + 血缘 + 增量幂等 ETL**：临床数据可追溯、可回放。
- **数据质量与隐私分级**：16 类敏感字段脱敏，字段级加密。
- **科研闭环**：专病队列按入排标准自动匹配、脱敏导出（CSV/RFC4180）、描述统计/Welch t/卡方自动分析。

### 2.3 AI 中台 —— 模型可插拔，能力可生长
- **LLM 适配层**：OpenAI 兼容接口，endpoint/key/model 全部从环境变量读取，本地确定性与云端模型可切换；外部不可用时自动熔断降级，绝不拖垮业务。
- **RAG 知识中台**：文档摄入→解析分块→向量化→检索增强，院内知识库可插拔。
- **DAMO-RADAR 影像大模型**（见第四节）。
- **智能体编排器（Orchestrator）+ 工具注册中心（Tool Registry）**：Agent 通过受控工具调用业务能力，每一步可审计。

## 三、AI 灵魂：MEDMUSE 与医生个人智能体 DOCTOR_MUSE

### 3.1 五岗位 Personal Agent
医院里每一个角色，都有一个专属智能体，沉淀该角色的经验：

| 智能体 | 服务对象 | 沉淀的经验 |
|---|---|---|
| **Doctor MUSE** | 医生 | 诊断思路、用药选择、病历写法、成功/失败病例 |
| **Nurse MUSE** | 护士 | 护理评估、交接班、不良事件处置 |
| **Pharma MUSE** | 药师 | 处方审核、相互作用、库存预警 |
| **Admin MUSE** | 管理者 | 运营分析、质控整改、资源调配 |
| **Patient MUSE** | 患者/家属 | 随访、依从性、健康教育 |

### 3.2 DOCTOR_MUSE：让每个医生的经验变成医院的资产
- 医生在日常诊疗中的每一次**采纳、修改、驳回**Agent 建议，都被记录为一个"学习点"；
- 成功路径被强化、失败路径被回灌，**个人 Agent 越用越贴合作者的风格与判断**；
- 当医生晋升、调动、退休，其沉淀的经验以受控方式留在医院底座上——**下一位医生不是从零开始，而是站在前人的肩膀上**。
- 这就是"越用越聪明"的技术落地：**经验不随人走，能力在组织级复利增长**。

### 3.3 学习飞轮（Learning Flywheel）
```
使用 → 记录反馈（采纳/修改/驳回）→ 沉淀到岗位 Agent
     → 同类场景下建议更准 → 更多使用 → 数据更厚 → 模型/规则更强
```

## 四、影像 AI：DAMO-RADAR 开源影像大模型集成

JLMEDAIOS 通过独立推理服务（`services/radar-inference`，默认 `http://localhost:8090`）集成 **达摩系开源医学影像大模型 DAMO-RADAR**，在实验室阶段已打通从"片子"到"结构化报告 + 医师复核"的完整闭环：

- **覆盖范围**：静态目录 **18 个器官 / 146 类影像发现（finding）** 的识别与辅助诊断；
- **任务化**：提交分析任务（PACS / 上传 / demo）→ 异步进度 → 结构化结果；
- **危急值联动**：`critical` 阳性发现经既有 `critical:alert` 实时通道推送到医生工作站；
- **医师复核闭环**：AI 结果必须经医师 **approve / modify / reject + 电子签名** 才生效，全程写审计留痕；
- **韧性**：推理服务不可用（连接拒绝/超时/熔断打开）时自动降级为确定性 mock，保证前端闭环不崩；生产联调时一键切回真实模型。

> ⚕️ **医疗红线**：影像 AI 始终是"第二意见"，不做自主诊断，不替代医师签名。

## 六、生产级安全与合规（医院上线红线）

- **权限**：RBAC + ABAC，每个写操作走 `guarded('permission:code')`，权限码集中管理；
- **审计**：所有写操作记录 who/when/what，审计日志哈希链可追溯；
- **幂等**：写操作支持 `Idempotency-Key`，网络重试不产生重复业务；
- **脱敏**：患者姓名/身份证/手机号等 16 类敏感字段字段级脱敏展示；
- **加密**：AES-256-GCM，等保三级设计，MFA，JWT 主动吊销；
- **韧性**：指数退避重试、滑动窗口熔断、限流、Saga 分布式事务、Transactional Outbox、死信队列、断连补拉；
- **失败降级**：任何外部依赖（LLM/影像推理/PG）不可用时业务不崩，自动降级；
- **数据不出院**：支持私有化部署，院内闭环。
