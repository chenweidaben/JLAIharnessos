# 容灾与恢复演练手册（DR Runbook）

> 本手册规定健澜科技杠OS 的备份恢复**验证**与容灾演练流程。备份策略与命令基础见
> 《04-备份恢复手册》，脚本见 `deploy/postgres/backup.sh`、`deploy/postgres/restore.sh`。
> **未经过演练验证的备份等于没有备份**——所有恢复路径必须周期性实测。

## 1. 目标（与《04》一致）

| 指标 | 目标 | 说明 |
| ---- | ---- | ---- |
| RTO（恢复时间目标） | ≤ 30 分钟 | 从故障判定到核心业务恢复 |
| RPO（数据丢失目标） | ≤ 5 分钟 | 依赖 WAL 实时归档；审计日志目标 RPO=0（实时双写） |
| 备份可恢复率 | 100% | 每次备份均可在隔离环境成功恢复并通过校验 |

> 上述为基线目标，部署方应按医院业务连续性要求调整，并在演练中实测验证。

## 2. 备份体系（三层）

1. **逻辑全量**：`backup.sh` 每日业务低峰 `pg_dump -Fc`，保留 ≥14 天，生成 SHA-256；
2. **物理 + WAL 归档（PITR）**：开启 PostgreSQL WAL 归档（`postgresql.conf` 的 `archive_mode=on`、
   `archive_command` 落盘到独立卷/对象存储），支持恢复到任意时间点；
3. **异地/异机副本**：备份与 WAL 至少一份在故障域之外（异机/对象存储），防主机与勒索软件同时损毁。

配套：Redis 持久化（AOF/RDB）、知识库对象与配置纳入备份；备份文件加密、最小权限访问。

## 3. 灾备架构分级（按医院规模选择）

- **L1 单机 + 异机备份**：适合试点/小型科室；依赖备份恢复，RTO 取决于重建速度。
- **L2 主从热备（流复制）**：一主一备，故障手动/自动提升备库，RTO 分钟级。
- **L3 高可用 + 异地容灾**：Patroni/托管 HA + 连接池 + 异地副本，定期切换演练。

应用层均为无状态多副本（BFF/Web），配合负载均衡摘流；状态集中在 PostgreSQL/Redis/对象存储。

## 4. 演练场景与步骤

### 场景 A：误删表/误数据（PITR，最高频）

1. 立即停止应用写入（功能降级开关/摘流），记录故障时刻；
2. 在**隔离恢复实例**恢复最近物理基础备份并重放 WAL 到误操作前一刻（`recovery_target_time`）；
3. 导出被误删数据，比对后回灌生产（或整体切换到恢复实例）；
4. 校验行数、关键业务表、审计哈希链完整性；
5. 恢复写入，记录实际 RTO/RPO。

> 严禁直接在生产库上做不可逆 PITR；先在隔离实例验证恢复点正确。

### 场景 B：整库损坏（逻辑恢复）

1. 新建干净数据库实例；
2. 校验备份 SHA-256：`sha256sum -c xxx.dump.sha256`；
3. 执行 `restore.sh <backup.dump>`（`pg_restore --clean --if-exists`）；
4. 运行 `bun scripts/db/check-sql.ts` 与业务冒烟（登录、患者检索、智能体运行）；
5. 切换连接串/数据源，观察监控与告警。

### 场景 C：数据库实例故障（主备切换）

1. 监控/探针确认主库不可达，排除网络抖动（两次探测 + 人工确认，防脑裂）；
2. 提升备库为主（`pg_promote` / Patroni `switchover`），确认复制追平；
3. 更新连接串/连接池/HA VIP，应用重连；
4. 旧主隔离，修复后以备库身份重新加入，校验数据一致；
5. 记录切换耗时与数据缺口。

### 场景 D：整机/机房故障（异地恢复）

1. 宣告灾难，启动应急小组与通讯树；
2. 在备用站点用异地备份/WAL 重建数据库与对象存储；
3. 部署应用镜像（同版本 digest）、注入密钥、导入配置；
4. 按上线清单做最小化健康/业务验证后切流；
5. 对外通告与临床应急（必要时回退纸质流程）。

### 场景 E：中间件故障降级

- **Redis 不可用**：切换/重启，应用回源数据库，验证缓存降级不产生脏数据；
- **Kafka 不可用**：消息落本地/重试，验证死信与补偿，恢复后不丢不重；
- **Elasticsearch/知识库不可用**：检索降级为关键词/数据库检索，CDS 规则类能力不受影响；
- **HIS/LIS 适配器故障**：熔断打开、排队与人工兜底，恢复后补单核对。

## 7. 验收标准

- 恢复后应用 `typecheck/test` 不必重跑，但**业务冒烟必须通过**：登录、患者 360、
  智能体运行、危急值闭环、审计可查；
- 数据库约束、索引、扩展（pgvector）、种子/术语数据完整；
- 审计日志哈希链校验连续，无断链；
- 实测 RTO/RPO 达标；不达标须输出容量/流程整改并复测。
