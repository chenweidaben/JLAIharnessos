## 1. 概述

本文档定义数智医院智能体的测试分层策略、覆盖率目标、数据与环境管理规范，以及 CI/CD 流水线要求。测试框架统一使用 **bun test**，全部基于 Mock 数据，不依赖真实 HIS / LIS / PACS 系统。

### 验证标准（本阶段达成情况）

| 指标 | 目标 | 实测 |
| --- | --- | --- |
| 单元测试通过 | 全部通过 | 898 用例全通过 |
| 集成/E2E 场景测试 | 5 个医疗场景通过 | 26 用例全通过 |
| Prompt 注入检测率 | > 95% | 52 样本检测率 100% |
| 只读工具平均响应 | < 100ms | 实测 < 1ms（Mock 环境） |
| 代码行覆盖率 | > 80% | 86.29% |

## 2. 测试分层策略

```
┌─────────────────────────────────────────────┐
│ L5 安全测试  tests/security/                 │  注入/SQL/XSS/命令注入 检测率验证
├─────────────────────────────────────────────┤
│ L4 性能测试  tests/performance/               │  响应时延 / Token预算 / 并发
├─────────────────────────────────────────────┤
│ L3 端到端医疗场景  tests/integration/         │  5 个临床全流程编排
├─────────────────────────────────────────────┤
│ L2 模块集成  tests/unit/integration/ 等       │  适配器/总线/CDS/工具编排
├─────────────────────────────────────────────┤
│ L1 单元测试  tests/unit/                      │  核心类/函数/工具逐一断言
└─────────────────────────────────────────────┘
```

- **L1 单元测试**：纯函数与类方法，Mock 一切外部依赖；每个用例独立、可重复。
- **L2 模块集成**：验证模块间接口契约（适配器↔工具、CDS↔安全、注册表↔执行器）。
- **L3 端到端**：以真实临床角色视角编排多个工具，验证跨步骤数据流与状态流转。
- **L4 性能**：开发环境软阈值，仅记录趋势，不阻断发布。
- **L5 安全**：以攻击模式库做检测率回归，禁止真实攻击目标。

## 4. 测试数据管理

- 所有患者、就诊、病历、医嘱、检验、影像数据来自 `src/medical-tools/mockData.ts`，均为虚构数据，不含真实患者隐私。
- 上下文构造统一走 `tests/unit/medical-tools/helpers.ts` 的 `createMedicalToolContext({ role })`，覆盖医师/护士/药师等角色。
- 严格禁止在测试中写真实外网地址、真实身份证/手机号；所有敏感字段断言"脱敏后不可还原原文"。
- **测试隔离**：不依赖文件系统共享状态；涉及种子数据状态流转的用例，避免跨用例变更同一条种子记录（如处方 RX20260910002）。

## 5. 覆盖率目标与报告

- 行覆盖率目标 **> 80%**，函数覆盖率持续提升。
- 生成命令：

```bash
bun test --coverage
```

- 本阶段实测行覆盖率 86.29%。新增模块提交时不得使行覆盖率下降。

## 6. CI/CD 流水线要求

1. **提交触发**：`bun test` 全绿方可合并；安全测试注入检测率必须 ≥95%。
2. **覆盖率门禁**：`bun test --coverage` 行覆盖率不得低于基线。
3. **失败处理**：
   - 用例失败 → 阻断合并，附失败堆栈。
   - 偶发/时序型失败（如日志轮转、错误监控聚合）→ 在本地多轮复现确认后，标记为已知问题并修复隔离性。
4. **性能基准**：每次主分支合并记录工具平均响应时延，超阈值（只读 >100ms）生成趋势告警。

## 7. 已知限制

- LLM 流式网络部分通过 `ILLMClient` 契约与模型配置间接覆盖，不发起真实 API 调用。
- 性能数据来自开发环境 Mock，仅供相对趋势参考，不作为生产 SLA 依据。
- 安全测试仅做检测能力验证，不针对真实系统发起攻击。
