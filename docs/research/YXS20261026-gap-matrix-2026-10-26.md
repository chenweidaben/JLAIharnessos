## 1. 方案要点摘要（对标基线）

### 1.1 建设目标

- **四个减负**：医师文书负担、护士重复录入、质控抽检（转全量）、管理事后处置（转实时）。
- **四个提升**：书写规范完整性、内涵质量、质量安全精细化、就医体验与数智形象。

### 1.2 建设边界（方案明确，开发不得越界）

- 不改动、不替换医院现有 HIS/EMR 等核心业务系统；
- 不新增算力采购，利旧医院现有算力；
- 不含面向患者的互联网端应用。

### 1.3 总体结构

- **一个平台、六个智能体**：平台六子系统 = 网关管理、模型管理、RAG 私域知识库、提示词工程管理、智能体管理、安全审计；六智能体 = 门诊病历、住院病历、手术记录、会诊记录、护理记录、病历内涵质控（预留扩展位）。
- **五横两纵六层架构**：基础设施层（利旧）、数据与接入层、模型管理层、智能体应用层、用户与场景层；两纵 = 安全保障体系、标准规范与运营体系。
- **技术路线**：通用大模型 + 规则引擎 + 专用小模型混合；RAG 为核心知识增强；私有化部署 + 统一模型网关；事件总线驱动智能体协同（手术记录完成触发质控、质控发现问题触发提醒）。
- **三阶段实施**：① 平台部署 + 模型上线 + 知识库初始化 + HIS/EMR 对接 + 门诊/住院智能体 2–3 科室试点；② 手术/会诊/护理三智能体 + 内涵质控（先运行病历实时提醒，再终末质控）；③ 全院推广 + 能力开放 + 自有提示词/知识/最佳实践沉淀。

### 1.4 关键机制要求（本矩阵逐项对照的清单）

- **模型层**：模型注册、健康检查、版本回滚、A-B 测试；主力/辅助/专用三层模型；统一 OpenAI 标准抽象层；模型卡片；按科室/任务/长度/时延/负载/成本策略路由；健康探针热切换无缝降级；会话粘性（患者/就诊标识一致性哈希固定版本）。
- **模型安全五道防线**：输入侧敏感识别 + 注入检测；提示词约束；知识约束（检索不到明确拒答）；输出侧校验（虚构患者信息、与原始数据矛盾、格式、确定性诊断、敏感词红线）；全过程审计（输入摘要/输出/模型版本/调用者/时间/耗时/是否采纳，多维检索）。
- **RAG**：六知识域；采集接入 → 格式解析结构化 → 清洗规范化 → 切分 → 向量化索引（向量 + 关键词倒排 + 结构化标量三路）→ 混合检索重排 → 引用溯源；患者诊疗数据不入向量库，实时接口按就诊标识精确获取；历史相似病例另建患者级隔离索引、强制标识过滤、禁止跨患者召回；相似度低于阈值判无依据如实提示；准入审核 + 生效/失效日期 + 过期转历史；冲突检测 + 版本链；季度评审。
- **提示词**：系统级 / 场景级 / 科室级 / 任务级动态四层；结构化 JSON Schema 输出 + 校验重试降级；Few-shot 2–5 例；思维链分步；引用标注 +「（待核实）」+ 缺失留空；分类目录、版本变更记录对比回滚、采纳率/修改字数异常反馈监控告警、资产加密归属医院。
- **编排九能力**：可视化拖拽流程（取数/知识检索/模型调用/条件分支/循环/并行/人工确认/格式校验/回写/通知/异常处理，子流程嵌套）；意图识别 + 任务规划；Function Calling 工具集（含参数/权限/频次限制）；上下文管理（会话/患者/历史，长住院摘要 + 关键节点压缩，跨会话持久化状态）；多智能体协同（串行/并行/主从/评审，标准消息格式解耦）；人工确认三模式（全量/差异/抽样，采纳/修改/拒绝/多轮指令）；异常处理降级（超时重试 → 备用模型 → 转人工提示手工书写）；运行监控（执行轨迹/节点耗时/模型调用/人工干预点/完成率/平均耗时/人工修改率）；全链路追踪 + 断点接续（唯一链路标识串联取数/检索/模型版本/节点耗时/输出/最终处置；跨会话保留上下文与状态可恢复点接续）。
- **智能体生命周期**：注册准入（名称/部门/责任人/场景/数据范围/输出类型/风险等级/模型知识依赖/接口清单）；三级风险（低 = 操作问答摘要、中 = 文书生成需医师确认、高 = 质控结论/诊疗建议需专家复核）；上线前三类评测（功能/质量/安全对抗边界合规）；运行监控采纳率/修改率/反馈/异常率；灰度 + 回滚；退役留痕。
- **升级体系**：四条独立版本线（平台程序/模型/知识库/提示词规则）；四维留痕（模型 + 知识 + 提示词 + 发布版本，病历法律举证可追溯）；六类升级；四级管控；五维灰度（科室/医师/文书类型/患者/流量比例）；模型升级七步（准入评测三硬门槛 → 影子加载 → 影子比对盲评 → 小流量灰度 → 指标比对 → 逐档放量 → 全量切换归档）；回滚顺序先流量 → 配置 → 模型 → 程序 → 数据；四环境隔离（开发/测试/预生产/生产）；接口兼容四策略（版本化/字段只增不删/弃用提前公告/灰度双版本并行）；业务连续性三层（功能降级回手工/只读兜底/人工支援）；在途业务三规则（升级前快照/期间排队不返回半成品/完成后按快照核对）+ 幂等防重复回写。

### 2.3 两套智能体体系并存（架构整合必须先决策的现状事实）

**体系 A：岗位智能体注册表**（`src/bff/agents/agentRegistry.ts`，117 行）
