## 1. 为什么采用 Strangler（绞杀者）模式

医院信息系统是**持续运行、不可中断、强合规**的关键业务系统。推倒重来（big-bang）风险极高：切换即全有或全无、回滚困难、历史数据与流程易丢失。因此 jlmedaios 采用 Martin Fowler 提出的 **Strangler Fig（绞杀者）模式**：

1. 在既有系统前架设**门面 / 网关（Facade）**，逐步接管请求路由；
2. 按领域**增量实现新服务**，与旧实现并行运行；
3. 逐个用新服务替换旧实现并**切换流量**；
4. 旧能力被完全替代后再**清理下线**；
5. 每一步系统都可运行、可验证、可回滚。

在本项目中，"被绞杀的对象"包括：①早期的内存 mock 数据与写死规则；②单体式 BFF 中尚未按领域拆分的逻辑；③未来院方既有 HIS/EMR 的旧模块。

## 3. 里程碑总览

```
M0 门诊真实闭环(已完成)
   └─ M1 住院 + 急诊核心事务
        └─ M2 医嘱处方/病历/药事深化 + 刚需技能包(AI病历质控·语音病历)
             └─ M3 收费结算 + 医保 DRG-DIP + 病案首页
                  └─ M4 知识中台/RAG 增强 + 低代码 Agent/技能编排平台
                       └─ M5 多租户一院多区 + 医疗大数据湖仓/科研专病库
                            └─ M6 云原生生产化(K8s/服务网格) + 等保三级/MFA/真实外部系统联调
```

| 里程碑 | 主题 | 核心交付 | 价值 |
|---|---|---|---|
| **M1** | 住院 + 急诊 | ADT、床位病区、查房护理、急诊分诊/绿色通道 | 覆盖医院主要高频场景 |
| **M2** | 事务深化 + 刚需技能 | 医嘱/处方/药事全流程、AI 病历质控、语音病历、审方 | 直接减负、降低差错 |
| **M3** | 收费/医保/病案 | 收费结算、DRG-DIP、票据、病案首页与编码 | 业务闭环、合规评级 |
| **M4** | 知识中台 + 低代码 | RAG 增强、知识/技能/Agent 可视化编排 | 信息科可自建、生态化 |
| **M5** | 多租户 + 大数据 | 一院多区、多租户、湖仓、专病库、随访 | 集团化、科研、真实世界证据 |
| **M6** | 生产化/联调 | K8s/网格、等保三级、MFA、HIS/EMR/LIS/PACS 真实联调 | 三甲真实生产上线 |

> 时间安排遵循"慢工出细活"：每个里程碑以"达到 DoD"而非固定日历为完成标准；宁可延长，不留隐患。

## 4. 各里程碑范围与验收

### M1 — 住院 + 急诊核心事务
**范围**
- 住院：入院/出院/转科（ADT）、床位与病区、住院就诊、查房、护理记录、在院医嘱视图；
- 急诊：分诊分级（1–4 级）、绿色通道、抢救记录、急诊留观；
- 数据：补齐住院/急诊表结构与种子（多病区、床位图、当日住院/急诊患者）；
- 前端：住院床位图/查房工作台、急诊分诊屏，去 mock。

**验收（DoD）**
- 真实完成 入院→床位分配→查房→医嘱/病历→出院，psql 取证、重启不丢；
- 急诊分诊分级正确、绿色通道流程闭环；
- 危急值从检验结果到通知/确认闭环；
- 前后端 tsc 0、测试全绿且新增覆盖；越权/数据范围正确。

### M2 — 医嘱处方/病历/药事深化 + 刚需技能包
**范围**
- 医嘱：长期/临时医嘱、医嘱组、执行单、停止/取消（高风险双签）；
- 处方/药事：处方全流程、发药/调剂、库存联动、用药监护、相互作用/过敏/剂量校验；
- 病历文书：更多文书类型、模板、三级质控、签名链；
- 技能包：**AI 病历质控（缺陷/时限/完整性）、语音电子病历、智能审方、检查检验解读**。

**验收**
- 高风险医嘱/处方双签名与药师审核闭环；库存写操作真实联动；
- AI 病历质控能检出真实缺陷并给出可追溯依据；语音转写结构化入病历；
- CDS 拦截/提醒在真实流程中触发，override 留痕；
- 全量测试 + E2E（住院查房、处方审核）通过。

### M3 — 收费结算 + 医保 DRG-DIP + 病案
**范围**
- 门诊/住院收费、费用明细、票据、退费（含补偿）；
- 医保对接、**DRG/DIP 分组与结算**、对账；
- 病案首页、归档、ICD/手术编码、上报与质控。

**验收**
- "就诊/出院→费用→结算→票据"真实闭环，金额可追溯、退费有补偿；
- DRG/DIP 分组结果可解释、可复核；
- 病案首页数据由临床数据自动汇聚、编码可校验；
- Saga 跨服务一致性经异常演练（失败/补偿）验证。

### M4 — 知识中台/RAG 增强 + 低代码编排平台
**范围**
- 知识中台：权威开放知识库批量导入、向量检索增强、知识版本与权限；
- 低代码：**可视化 Agent 编排（拖拽节点）、技能编辑器、页面/表单装配**，发布与版本管理；
- 让信息科无需深研代码即可产出 AI 病历、AI 质控、语音病历等智能体。

**验收**
- 信息科用低代码平台从零搭建并发布一个真实可用智能体（真数据、真 LLM、可落库）；
- RAG 回答带来源引用、可追溯；
- 编排的智能体经测试与权限校验，高风险节点强制人工；
- 平台产物纳入版本与审计。

### M5 — 多租户一院多区 + 医疗大数据湖仓
**范围**
- 多租户/一院多区全量落地（隔离、院区差异化、集团汇总）；
- CDC → 湖仓分层、主数据治理、科研专病库、随访队列；
- 数据质量、血缘、隐私分级与脱敏。

**验收**
- 跨租户访问默认拒绝、隔离测试通过；院区数据独立且集团汇总准确；
- 专病库可构建队列、支撑科研分析；
- 数据治理（质量/血缘/分级）可验证；
- 性能在多院区数据量下经真实压测达标。

### M6 — 云原生生产化 + 安全/联调
**范围**
- K8s/服务网格/多集群、灰度发布、可观测、容量与灾备；
- 等保 2.0 三级全控制域、**MFA**、密钥管理；
- HIS/EMR/LIS/PACS **真实系统联调**（从 Mock 切换）、真实 SSO；
- 上线前全要素验收与试运行。

**验收（上线门）**
- 等保三级测评通过（含 MFA）、安全测试无高危；
- 真实外部系统端到端联调通过、异常切换/降级有效；
- 生产压测达容量目标、故障演练（节点/可用区/依赖故障）通过；
- 备份恢复演练成功、可观测告警闭环；
- 上线 checklist 全签、回滚预案就绪。

## 5. 每个领域的标准迁移手法（Strangler 四步）

对任一待替换能力，统一执行：

1. **门面拦截（Facade）**：在 BFF/网关确定该能力的唯一入口与契约（请求/响应/事件），旧实现仍在其后服务；
2. **并行实现（Parallel）**：在新模块/微服务中实现同一契约，真实读写 PostgreSQL；用**特性开关（Feature Flag）**控制新旧切换；
3. **对比与切换（Compare & Switch）**：对同一输入比对新旧结果（影子流量/并行校验），达标后按租户/院区/比例灰度切到新实现；
4. **清理下线（Retire）**：观察稳定后删除旧实现与开关，更新契约与文档。

> 全程坚持：**真实模式连真库/真 LLM；连不上即明确报错**；演示数据只在显式 `DEMO_MODE` 下水印存在，绝不以假乱真。

---

## 6. 契约与事件治理（避免"链路不通"）

- **API 契约优先**：跨服务/前后端先定 OpenAPI/类型契约与示例，再并行开发；契约纳入评审与自动化校验（前后端类型对齐）；
- **事件 Schema 注册**：每个领域事件登记名称、字段、版本、生产者/消费者；Schema 演进向后兼容、破坏性变更升版本；
- **幂等与一致性**：消费者幂等（去重键）、消息至少一次 + 幂等 = 等效恰好一次；Saga 每步可补偿；
- **契约测试**：生产者/消费者契约测试纳入 CI，防止"各自都绿、集成即断"。

---

## 7. 统一验收门（DoD，所有里程碑通用）

一个里程碑只有同时满足才算完成：

1. 数据真落 PostgreSQL、关键写可查回、**重启不丢**（psql 证据）；
2. 真实 LLM 流式 + ReAct 工具闭环、消息落库；失败明确报错、演示带水印；
3. 正向 + 异常业务闭环（含越权、超时、补偿、降级）；
4. 前后端 tsc 0、测试全绿、覆盖率 ≥85%、关键 E2E 通过；
5. RBAC+ABAC、数据范围、多租户隔离经测试；安全无高危；
6. 可部署（"下载就能跑"）、可观测、可回滚；
7. 中英文档与许可证 SBOM 同步更新。

---

## 8. 回滚策略

- **特性开关级**：发现问题一键切回旧实现（秒级，无需重新部署）；
- **版本级**：镜像/配置版本化，灰度异常按比例/按院区回退；
- **数据级**：变更采用兼容式（扩展不破坏），迁移提供反向脚本；关键写操作保留版本与痕迹；
- **事务级**：Saga 失败触发补偿，恢复到一致状态；
- 每次切换前明确"回滚触发条件、负责人、最长恢复时间（RTO）与数据点（RPO）"。

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 范围膨胀、追求一步到位 | 烂尾、质量下降 | 严守里程碑、每阶段 DoD、宁慢勿错 |
| 跨服务集成断裂 | 链路不通 | 契约优先、契约测试、事件 Schema 治理 |
| 高并发性能不足 | 高峰期故障 | 无状态+缓存+事件削峰+真实压测 |
| 医疗安全/合规缺陷 | 差错、违规 | 双签名、CDS、审计、等保、权限最小化 |
| 外部系统联调延迟 | 进度受阻 | 适配器+显式 Mock 先行，院方接口尽早介入 |
| 数据迁移/一致性 | 数据丢失 | 兼容演进、CDC 校验、备份恢复演练 |
| 模型不可用/越权 | 服务中断/风险 | 多供应商可插拔、降级、人工兜底、AI 不自主诊疗 |

## 10. 团队组织与并行（多 Agent 协作）

- 按里程碑与领域分片：**核心事务 / AI 能力 / 数据平台 / 集成标准 / 前端体验 / 测试质量 / 平台运维**；
- 每个领域独立 Agent/团队端到端负责（实现→测试→文档），跨片先对齐契约；
- 主控负责架构仲裁、DoD 把关、真实取证与最终整合；
- 统一分支策略、语义化提交、CI/CD 与代码评审；
- 完成后同步 GitHub + GitCode，核对三方 HEAD 并打里程碑 tag（如 v0.3.0-m1 …）。
