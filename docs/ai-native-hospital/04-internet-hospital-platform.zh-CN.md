## 1. 背景与目标

### 1.1 建设背景

jlmedaios 已在院内侧完成门诊、住院、医嘱处方、病历文书、收费结算、药事、检验检查、手术麻醉、病案、预约随访等核心域的闭环（M0–M3-I）。本平台在此基础上向**院外（互联网）延伸**，构建"**一所实体医院 + 一个互联网医院 + 多端患者入口**"的一体化服务体系。

政策与合规依据：

- 《国家卫生健康委办公厅关于印发医院智慧服务分级评估标准体系（试行）的通知》（国卫办医函〔2019〕236 号，4S 体系）；
- 《互联网医院管理办法（试行）》《互联网诊疗管理办法（试行）》《远程医疗服务管理规范（试行）》（国卫医发〔2018〕25 号）；
- 《互联网诊疗监管细则（试行）》（国卫办医发〔2022〕2 号）；
- 各省（市）互联网医院管理办法、互联网医疗服务监管平台对接标准；
- 网络安全等级保护 2.0（互联网医院核心系统**第三级**）、《数据安全法》《个人信息保护法》。

### 1.2 建设目标

1. **达标**：建成后满足**国家医院智慧服务三级**（"联通医院内外的智慧服务初步建立"），并为四级（区域互联、全流程个性化）预留演进路径。
2. **一体**：互联网诊疗产生的病历、处方、收费、随访数据与院内 EMR/HIS 实时互通、统一主索引、统一签名与审计，杜绝"线上线下两张皮"。
3. **可用**：按大三甲（一院多区、日门诊上万、注册用户数百万、峰值并发数千）真实生产标准设计，7×24 小时不间断，支持弹性伸缩与灰度发布。
4. **合规**：全程留痕、可追溯，主动对接省级互联网医疗服务监管平台、医保信息平台、电子处方流转平台，AI 仅辅助、医师/药师本人签名。
5. **便民**：以微信小程序为主入口，覆盖预约、问诊、处方、支付、配送、报告、住院、随访、评价全流程，并提供适老化与数字陪诊。

## 2. 技术选型决策

### 2.1 结论

| 层 | 选型 | 说明 |
|---|---|---|
| 互联网医院后端（业务/BFF/网关） | **TypeScript + Bun**（与 jlmedaios 同栈） | 复用院内全部领域能力，统一类型契约与工程规范 |
| 患者端 | **微信小程序（原生 WXML/WXSS + 组件化）**，同步评估 **Taro 跨端**（微信/支付宝/H5/APP） | 优先微信生态；跨端复用降低多端成本 |
| 医生/药师线上工作站 | 复用现有 **React 19 + Vite + Ant Design 5** Web 端，新增线上接诊/视频模块 | 不重复建设，统一工作台 |
| 音视频问诊 | 第三方**实时音视频 RTC SDK**（腾讯云 TRTC / 阿里云 ART C / 声网 Agora，可插拔）+ 图文 IM | 自研 WebRTC 不满足医疗级与合规，采用持证厂商 |
| 数据库 | PostgreSQL 16（院内/互联网同库或独立实例 + CDC 同步） | 强一致、JSONB、分区、行级安全 |
| 缓存/会话/锁 | Redis（会话、验证码、号源、限流、分布式锁） | 无状态化前置 |
| 消息/事件 | Kafka（或 RedPanda）：IM 消息、业务事件、削峰、监管上报 | 异步解耦 |
| 外部对接 | **网关/中台隔离层**：监管网关、医保网关、支付网关、处方流转网关 | 业务系统不直连外部平台 |
| 异构服务接入 | 标准 REST/gRPC + FHIR，**允许 Java/Spring Boot 等异构服务接入** | 兼容招标对 Java 的要求，不强制重写核心 |

### 2.2 为什么后端继续用 TypeScript/Bun 而非整体改 Java

1. **复用最大化**：互联网医院不是孤立系统，约 70% 能力（病历、医嘱、处方、收费、药品、随访、质控、签名、审计、权限）已在 jlmedaios 以 TypeScript 实现并经测试与取证。改 Java 等于重写并长期维护两套栈，成本与风险极高。
2. **同栈契约一致**：Bun/TypeScript 与前端共享类型定义，端到端类型安全，减少接口联调缺陷；Bun 启动快、吞吐高、原生支持 fetch/TS/测试，满足医疗事务性能。
3. **云原生无语言障碍**：容器化、K8s、服务网格、可观测性、等保三级均与语言无关；TypeScript 服务可无状态水平扩展。
4. **Java 诉求通过开放架构满足**：大三甲招标常列 Java，但本质要求是"成熟、可维护、可集成、人才可获得"。本平台通过标准 API/FHIR/gRPC 允许 Java 异构服务（如医院既有的 Java 医保前置、区域协同服务）接入，并提供完整的接口文档与运维手册；**不做"为 Java 而 Java"的全量重写**。
5. **AI 原生优势**：TypeScript 与 AI Agent/工具调用、结构化输出（JSON Schema）、流式响应天然契合，便于把智能导诊、预问诊、AI 辅助贯穿线上线下。

> 若个别医院明确要求"全院 Java 信创栈"，可在交付阶段以**适配层 + 异构服务**方式满足，核心引擎保持不变；该边界在商务与技术方案中明确，不影响开源主线。

## 3. 总体架构

### 3.1 互联网医院在 jlmedaios 六层架构中的位置

互联网医院作为**面向患者的"第二接入域 + 患者服务域"**，横向复用院内中台，纵向通过隔离网关对接外部平台：

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 患者接入            微信小程序(主) · 微信公众号 · H5 · 支付宝小程序(可选) · APP(可选) │
│ 医护接入            现有 Web 工作站（新增线上接诊/视频/审方模块）· 移动医护(可选)      │
├──────────────────────────────────────────────────────────────────────────┤
│ 互联网医院 BFF / API 网关（独立部署、DMZ 区、WAF、限流、鉴权、灰度）                   │
│  患者服务编排：实名/就诊人 · 预约挂号 · 在线问诊 · 电子处方 · 在线支付 · 药品配送       │
│               报告查询 · 住院服务 · 随访 · 满意度 · 智能导诊/预问诊/数字陪诊           │
├──────────────────────────────────────────────────────────────────────────┤
│ 外部对接网关（隔离层，可插拔、可重放、可降级）                                        │
│  监管网关   医保网关   支付网关(微信/支付宝)   处方流转网关   物流网关   实名认证网关   │
│  电子票据   音视频RTC(IM)   消息推送(订阅消息/短信)   电子签章/CA                        │
├──────────────────────────────────────────────────────────────────────────┤
│ 复用 jlmedaios 院内核心（HIS+EMR 一体化微服务）                                     │
│  门诊·住院·医嘱处方·病历文书·收费结算·药事·检验检查·手术麻醉·病案·排班随访·AI 中台    │
├──────────────────────────────────────────────────────────────────────────┤
│ 数据平台：PostgreSQL（RLS 行级安全）· EMPI · Redis · Kafka · 湖仓 · 专病/随访 · 监管库   │
└──────────────────────────────────────────────────────────────────────────┘
```

### 3.2 网络分区（生产部署）

- **公网区（DMZ）**：WAF、抗 DDoS、负载均衡、互联网医院 BFF、静态资源（小程序包不经此）。
- **外联区**：监管/医保/支付/处方/物流/实名等网关适配器，统一出口、白名单、TLS。
- **院内核心区**：HIS/EMR/数据库（不直接暴露公网），经 BFF/网关受控访问。
- **管理区**：运营管理、运维、审计、堡垒机。
- 区域间以防火墙 + NetworkPolicy 隔离，最小端口开放，跨区一律 TLS + 鉴权。

## 4. 患者端（微信小程序）功能架构

### 4.1 功能模块总览

| 分组 | 模块 | 核心能力 |
|---|---|---|
| 账户 | 实名注册/登录 | 微信授权登录、手机号、身份证 OCR、人脸识别（活体）、电子健康卡/医保电子凭证、就诊人管理（本人/老人/儿童，最多 5 人） |
| 诊前 | 智能导诊 | 症状人机对话（图文/语音）→ 推荐科室/医生；AI 预问诊采集病史并生成预问诊报告 |
| 诊前 | 预约挂号 | 科室/医生/号源查询、分时段预约、号源与院内实时同步、预约缴费、退号/改签、爽约黑名单 |
| 诊中 | 在线问诊 | 图文/语音/视频呼叫；选择复诊（须有明确诊断的历史就诊）；消息（文字/图片/语音）；医师端接诊 |
| 诊中 | 电子处方 | 医师在线开方（复诊限定、不得 AI 自动生成）、药师审核、处方详情、禁忌/相互作用提示、处方流转 |
| 诊中 | 在线支付 | 医保线上统筹结算 + 个账 + 自费（微信/支付宝）、移动支付、退费、电子票据（查验/下载） |
| 诊中 | 药品获取 | 院内药房自取（取药码/导航）、外配处方到定点药店、配送到家（地址/运费/物流跟踪） |
| 诊后 | 报告查询 | 检验/检查报告、影像云胶片、历史报告对比、报告解读（AI 辅助 + 医师复核） |
| 住院 | 住院服务 | 住院预约、入院登记、押金补缴、每日清单、手术进度、出院结算、床旁结算 |
| 诊后 | 健康管理 | 随访计划与记录、慢病管理、用药提醒、家医签约、健康档案、可穿戴设备接入（可选） |
| 全程 | 满意度 | 预约/接诊/收费/药房/检查分项评价、投诉建议、服务监督 |
| 适老 | 数字陪诊 | 大字体、语音交互、数字人全流程引导、代办、家属代办与授权 |
| 资讯 | 健康科普 | 院内发布的科普、就医指南、停诊通知、个性化推送 |

### 4.2 就诊人与实名认证（合规关键）

- **实名制**：患者须提供真实身份信息，禁止假冒；未成年人/无表达能力者须监护人陪同并登记监护人信息。
- 认证等级：L1 微信授权（手机号）→ L2 身份证 OCR + 人脸活体（强实名）→ L3 医保电子凭证/电子健康卡。
- **在线复诊、开处方、医保支付须 L2 及以上**；为 6 岁以下儿童开方须确认监护人及专业医师陪伴。
- 实名认证经**第三方实名网关**（公安/运营商/银行卡四要素）完成，敏感信息最小化采集、加密传输、不留存原始影像。
- 与院内 EMPI 打通：线上账号 ↔ 院内主索引（EMPI）↔ 就诊人，多端一人一档。

## 5. 医生端、药师端与管理端

### 5.1 医生端（线上接诊）

- **排班与开通**：资质（执业/职称/执业范围/临床年限）审核、线上排班、号源/接诊量设置、停诊/换诊。
- **接诊工作台**：待接诊/问诊中/已结束队列；图文 IM、语音、视频呼叫；查看患者历史线上线下病历、检验检查、诊断、用药。
- **在线诊疗**：填写复诊病历（可由 AI 预问诊/语音病历辅助生成，医师本人修改签名）、明确诊断、开具检验检查申请、开具处方（本人电子签名/CA）。
- **合规约束**：仅限复诊、常见病、慢性病；不得首诊确诊、不得开具麻醉/精神药品等禁限药品；不得 AI 自动生成处方；问诊时效（如 24 小时内接诊）。
- **患者管理与随访**：分组、标签、随访计划、复诊提醒、统计（接诊量、处方量、满意度）。

### 5.2 药师端（在线审方）

- 处方审核队列、在线/离线审方；四查十查、相互作用、禁忌、剂量、重复用药、适应症审核；
- 审核通过/退回（须理由），**处方经药师审核合格后方可生效**；用药指导（发药/配送时）；
- 处方流转与调剂、退药处理；审方统计与质量追溯。

### 5.3 管理端（运营/监管）

- 机构与人员资质（执业证、人员信息、执业范围）、科室/职称/角色权限；
- 业务运营：预约/问诊/处方/支付/配送/退费率、收入、医生绩效、统计报表；
- 内容管理：科普、首页、推送、消息模板；
- 监管对接：数据上报监控、补报、异常告警；
- 质控与风控：投诉、服务监督、违规预警、审计查询、黑名单（爽约/倒号/伤医）；
- 对账：支付/医保/票据/物流对账、差错处理。

## 6. 外部对接网关（隔离层）

> 核心原则：**业务系统不直连外部平台**，统一经"网关/中台隔离层"，便于协议适配、多地区切换、限流、重放、降级与审计。

| 网关 | 对接对象 | 关键能力 |
|---|---|---|
| 监管网关 | 省级互联网医疗服务监管平台 | 机构/人员/资质、问诊、处方、审方、收费、投诉等**全过程实时/准实时上报**；按省标协议；失败补报、留痕 |
| 医保网关 | 医保信息平台（移动支付/个账/统筹/电子凭证） | 医保中台隔离；支付/撤销/退费、对账、医保电子凭证授权；多城市切换 |
| 支付网关 | 微信支付、支付宝、聚合支付 | 统一下单、回调验签、退款、对账单、幂等 |
| 处方流转网关 | 电子处方流转平台/定点药店 | 处方上传、审方、配药、流转状态回传、可追溯 |
| 物流网关 | 第三方配送（顺丰/京东/美团等） | 下单、运单、轨迹、签收、运费、异常 |
| 实名认证网关 | 公安/运营商/银行/微信/支付宝实名 | 身份证核验、人脸活体、四要素、电子健康卡/医保凭证 |
| 音视频/IM | RTC 厂商（TRTC/ARTC/Agora） | 房间/令牌、呼叫、录制（合规留痕）、弱网、加密 |
| 消息推送 | 微信订阅消息/公众号/短信 | 通知模板、发送回执、退订 |
| 电子签章/CA | 第三方 CA、电子签名 | 医师/药师可靠电子签名、时间戳、验签、证书管理 |
| 电子票据 | 财政电子票据 | 开票、查验、下载、红冲 |

## 7. 核心业务流程

### 7.1 在线复诊 + 电子处方 + 医保支付 + 配送（主链路）

```
患者：实名登录 → 选就诊人 → 智能导诊/选科室医生 → 预约/发起复诊
  （校验：复诊资格=存在相同诊断的历史就诊；认证等级 L2）
医生：接诊 → 图文/视频问诊 → 查看历史病历 → 填写复诊病历（AI 辅助，本人签名）
      → 明确诊断 → 开检验检查/处方（本人电子签名，禁 AI 自动开方）
药师：收到处方 → 在线审核 → 通过/退回（理由）
系统：处方生效 → 费用归集（含药品/诊疗/检查）→ 患者选择取药方式
支付：医保网关（统筹+个账）/自费支付 → 支付成功 → 电子票据
取药：自取（取药码/导航）/外配定点药店/配送到家（物流跟踪）
诊后：随访计划（自动生成）→ 随访记录 → 满意度评价
全程：监管网关实时上报；审计哈希链留痕
```

### 7.2 状态机（关键域）

- **问诊会话**：`待接诊 → 问诊中 → 待药师审方（已开方）→ 待支付 → 待取药/配送 → 已完成`；异常分支：`已取消 / 已退号 / 已退费 / 已退回（整改）`。
- **电子处方**：`待审核 → 审核通过（生效）/ 审核退回 → 已缴费 → 已发药/已配送 → 已完成`；`已作废/已退药`。
- **支付**：`待支付 → 支付中 → 支付成功 → 已开票`；`支付失败/已退款（红冲）`。
- 所有状态转换采用**白名单 + 乐观锁（version）+ 行锁（FOR UPDATE）**，并发下保证不重复、可幂等。

### 7.3 异常与补偿（Saga）

- 支付成功但发药/配送失败：触发补偿（重发/换药店/自动退款 + 红冲票据）；
- 医保结算失败：回滚个账/自费、释放处方；
- 监管上报失败：进入重投队列，不阻断主流程但持续告警；
- 每步记录 Saga 日志（方向/状态/时间），支持人工干预与对账。

## 8. 数据架构与安全

### 8.1 数据组织

- **同库与分库策略**：初期可院内/互联网**同实例不同 schema + 行级安全（RLS）**；规模化后**独立互联网实例 + CDC（Kafka）双向/单向同步**，保证最终一致与故障隔离。
- EMPI 统一患者主索引，线上账号、就诊人、院内档案、医保/健康卡映射。
- 互联网侧核心表：患者账号、就诊人、问诊会话、IM 消息、处方（线上）、支付订单、配送单、随访、评价、监管上报、实名认证记录、音视频记录索引。
- 消息与录制：IM 消息、音视频录制（合规要求）按保存期限存储，加密、访问受控。

### 8.2 安全与隐私（等保三级）

- **身份与授权**：多因素认证、JWT 强签名、RBAC + ABAC + 数据范围（self/就诊人/科室/院区）；最小权限、职责分离（开方/审方/收费分离）。
- **数据保护**：TLS 1.2+ 传输、AES-256-GCM 静态加密、字段级加密（身份证/人脸/手机号）、**默认脱敏**（展示层姓名/手机号/证件号脱敏）、密钥分级管理（KMS）。
- **应用安全**：WAF、SQL/XSS/命令注入、参数化、IM/小程序内容安全（文本/图片鉴黄、敏感词）、防刷防爬、人机验证、接口签名与防重放。
- **审计**：哈希链防篡改审计、登录/操作/数据访问全留痕、可追溯；审计独立于业务账号。
- **合规**：个人信息最小必要、知情同意、隐私政策、数据出境管控、未成年人保护、删除/撤回授权。
- **高可用**：多可用区、多副本、自动故障转移、异地备份与恢复演练、RTO/RPO 目标（如 RTO≤30min、RPO≤5min）。

### 8.3 AI 边界（不可逾越）

- 智能导诊、预问诊、AI 数字陪诊、报告解读、病历/处方**辅助**均为建议；**所有诊断、处方、病历签名、审核结论由医师/药师本人确认与电子签名**；
- **严禁 AI 自动生成处方、严禁先药后方**；AI 输出须标注来源与不确定性，关键建议可追溯。

## 11. 部署与运维

- **容器化**：互联网 BFF、网关、服务均构建固定版本 OCI 镜像（非 root、最小、SBOM）。
- **编排**：K8s（HPA、PDB、反亲和、NetworkPolicy、Ingress + TLS）；Redis/PostgreSQL/Kafka 用 StatefulSet 或托管。
- **多环境**：dev/test/staging/prod 分离，配置中心 + 密钥管理（KMS/Secret），GitOps + IaC。
- **发布**：蓝绿/金丝雀、小程序灰度（按版本/比例）、回滚预案。
- **可观测**：统一日志（脱敏）、指标（Prometheus）、链路（OpenTelemetry）、业务大盘（问诊/支付/履约/监管）、告警值班。
- **容灾**：多可用区 + 异地备份 + 定期恢复演练；峰值压测（预约/秒杀/报告回传）。

## 12. 验收标准（生产可用）

1. 智慧服务三级达标（基本 8 项 + 选择 ≥4 项 + 总分 ≥30），可现场演示与取证；
2. 监管、医保、支付、处方流转、物流、实名、CA、电子票据全链路真实打通（非 mock）；
3. 全链路压测达标（响应时间、并发、可用性），7×24 稳定，故障自动切换与补偿；
4. 等保三级测评通过、数据安全与隐私合规、审计完整；
5. 线上线下数据一致、签名链完整、无假成功、无静默降级；
6. 文档齐全（架构/接口/部署/运维/用户手册，中英文），镜像与编排"下载可跑"。
