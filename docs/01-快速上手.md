# 快速上手指南

> 健澜科技数智医院智能体 · 5 分钟跑起来
> 版本 v1.0 ｜ 2026-09

## 1. 环境准备

| 软件 | 版本要求 |
| --- | --- |
| Bun | >= 1.3.0 |
| Node.js | >= 18 |
| PostgreSQL | 16 + pgvector（生产必需，开发可先用内置 Mock） |
| Redis | 7（生产必需） |

安装 Bun：

```bash
curl -fsSL https://bun.sh/install | bash
bun --version
```

## 2. 代码获取

```bash
git clone https://git.jianlan.tech/medical/jianlan-medical-agent.git
cd jianlan-medical-agent
```

## 3. 依赖安装

```bash
bun install
```

## 4. 配置

```bash
cp .env.example .env
```

按需填写：`DATABASE_URL`、`REDIS_URL`、`LLM_API_KEY`、集成适配器开关。开发阶段可使用内置 Mock 数据，不连接真实 HIS/LIS/PACS。

## 5. 启动

```bash
# 类型检查
bun run typecheck
# 开发模式（终端 CLI）
bun run dev
# 或启动服务端
bun run start:server
```

健康检查：

```bash
curl http://127.0.0.1:8080/health
# {"status":"ok"}
```

## 6. 第一个对话

启动终端后，以医生身份登录，输入自然语言：

```
> 帮我查一下 张 姓患者今天的门诊列表
```

智能体会自动选择 `query_patient` 等只读工具，返回脱敏后的患者列表。试着让它：

- "看看这个患者最近的检验结果" → `get_lab_result`
- "这份病历帮我写个门诊草稿" → `generate_medical_record`（需确认）
- "阿司匹林和氯吡格雷一起用安全吗" → `drug_interaction_check`

> 注意：开医嘱/处方（high 风险）会要求二次确认与资格校验，开发环境可用 Mock 数据体验。

## 7. 常用命令

| 命令 | 作用 |
| --- | --- |
| `bun run dev` | 开发模式（监听） |
| `bun run build` | 构建 |
| `bun test` | 运行测试 |
| `bun run typecheck` | 类型检查 |
| `bun run lint` | 代码检查 |

## 8. 常见问题

| 问题 | 解决 |
| --- | --- |
| Bun 版本过低 | 升级到 >=1.3.0 |
| 数据库连接失败 | 检查 PostgreSQL 与 pgvector 扩展 |
| 调不到 LLM | 核对 `LLM_API_KEY` 与网络 |
| 工具无权限 | 以 doctor 角色登录或调整权限点 |
