# 云原生部署

> 健澜科技数智医院智能体 · 微服务与云原生运维
> 版本 v1.0 ｜ 2026-09

## 1. 微服务架构部署

在容器化基础上，按业务域拆分为可独立伸缩的服务单元：

| 服务单元 | 职责 | 伸缩特征 |
| --- | --- | --- |
| agent-gateway | 接入与鉴权、会话 | 随在线医生数伸缩 |
| inference-worker | Agent 循环 / LLM 代理 | 随队列长度伸缩（CPU/网络密集） |
| cds-worker | CDS 规则评估 | 平稳 |
| rag-service | 检索/向量化 | 随检索 QPS 伸缩 |
| integration-bus | 外部系统对接 | 随集成流量伸缩 |

服务间通过消息队列（Redis Stream / 院内 MQ）解耦，危急值、检验结果等事件异步流转。

## 2. 服务网格（Istio）

- 以 Sidecar（Envoy）接管服务间通信，实现 mTLS、流量镜像、熔断与灰度；
- VirtualService 按版本路由：`canary` 副本承接 10% 流量观察；
- DestinationRule 配置连接池与异常检测，故障实例自动摘流。

## 3. 自动扩缩容（HPA）

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: { name: agent-gateway, namespace: medical }
spec:
  scaleTargetRef: { apiVersion: apps/v1, kind: Deployment, name: agent-gateway }
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource: { name: cpu, target: { type: Utilization, averageUtilization: 65 } }
```

- gateway/inference-worker 按 CPU + 自定义队列长度双指标扩缩；
- 冷却期 ≥ 5 分钟，避免抖动；LLM 长连接场景设置优雅终止（`terminationGracePeriodSeconds: 120`）。

## 4. 服务发现与负载均衡

- 集群内：Kubernetes Service + CoreDNS；
- 集群外：Ingress / SLB；
- 多 AZ 部署时，跨可用区副本分散，单 AZ 故障不影响整体。

## 5. 配置中心

- 非敏感配置集中于 ConfigMap / 院内配置中心（如 Nacos）；
- 敏感配置走 Secret / KMS，定期轮换；
- 配置变更走审核流程，变更后自动滚动重启相关副本并验证健康检查。

## 6. 日志聚合（ELK / Loki）

- 应用日志输出 stdout，由 Fluent Bit / Vector 采集；
- Loki + Grafana 或 Elasticsearch 存储；
- 结构化字段：`timestamp / level / userId / toolName / traceId / patientId(脱敏)`；
- 审计日志单独通道，不可被应用日志覆盖，保留 ≥ 15 年（合规要求）。

## 7. 监控告警（Prometheus / Grafana）

- Prometheus 抓取 `/metrics`（应用指标）与 node-exporter（主机）；
- Grafana 面板：系统、应用、业务、安全四类（详见 [监控手册](../operations/01-监控手册.md)）；
- AlertManager 按 P0–P3 分级路由通知（见 [告警手册](../operations/02-告警手册.md)）。

## 8. 云原生落地检查清单

- [ ] 日志/指标/链路三件套接入
- [ ] 配置与密钥分离，密钥定期轮换
- [ ] 灰度/回滚流程演练通过
- [ ] 数据不出院的网络策略与 mTLS 落实
