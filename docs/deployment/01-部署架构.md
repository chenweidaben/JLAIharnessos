## 1. 概述

健澜科技数智医院智能体基于 **Bun ≥ 1.3.0** 运行时与 **TypeScript 6.0（严格模式）** 构建，采用"终端 CLI（Ink）+ 服务端 API（Hono/Express）"双形态。生产部署时以服务端形态（`bun dist/server.js`）接入医院内网，前端终端/浏览器通过反向代理访问。

系统依赖的中间件：

| 组件 | 用途 |
| --- | --- |
| PostgreSQL 16 + pgvector | 业务数据 + 向量检索 |
| Redis 7 | 会话缓存 / 限流 / 任务队列 |
| MinIO（S3 兼容） | 病历文档、知识库原始文件对象存储 |
| Nginx | 反向代理 / TLS / 负载均衡 |

## 2. 三种部署模式

### 2.1 单机部署（开发/测试环境）

所有组件（应用、PostgreSQL、Redis、MinIO）部署于同一台服务器，适合开发联调、功能演示与测试验收。

```
┌──────────────────────── 单机 ────────────────────────┐
│  Nginx:443  →  app(Bun):8080                        │
│                PostgreSQL:5432  Redis:6379  MinIO:9000│
└──────────────────────────────────────────────────────┘
```

- 优点：部署简单、资源占用低、无网络复杂度。
- 局限：无高可用，不承载生产流量。

### 2.2 集群部署（生产环境）

应用多实例横向扩展，中间件主备/集群化，前置 Nginx 负载均衡。

```
            ┌───────── Nginx / SLB (443) ─────────┐
            │                                      │
     ┌──────┴──────┐                       ┌──────┴──────┐
   app-1 (Bun)  app-2 (Bun)  ...        app-N (Bun)
            │        │        │
     ┌──────┴────────┴────────┴──────┐
   PostgreSQL 主从   Redis 哨兵   MinIO 分布式
            │
     医院内网 HIS/EMR/LIS/PACS（经集成总线）
```

- 应用无状态，可水平扩缩；会话状态外置到 Redis。
- PostgreSQL 一主一/多从，流复制 + 自动故障切换。
- Redis 哨兵或 Cluster；MinIO 纠删码分布式。

### 2.3 混合部署（终端 + 云端）

医疗数据不出院，重推理负载可弹性上云。

```
院内侧：Nginx + app 网关 + PostgreSQL/MinIO（数据不出院）
   │ 加密专线 / VPN
云端侧：弹性推理网关（LLM 代理）+ 对象存储备份 + 监控聚合
```

- 患者原始数据驻留院内，仅经脱敏/加密后的必要上下文出网调用大模型。
- 满足《数据安全法》《个人信息保护法》与"医疗数据不出境"要求。

## 3. 硬件要求

| 规模 | CPU | 内存 | 磁盘 | 网络 |
| --- | --- | --- | --- | --- |
| 开发/单机 | 4 核 | 16 GB | 200 GB SSD | 千兆内网 |
| 生产小（≤500并发） | 8 核 ×2 | 32 GB ×2 | 1 TB SSD（RAID10） | 万兆内网 |
| 生产大（≥2000并发） | 16 核 ×≥3 | 64 GB ×≥3 | 5 TB SSD | 万兆 + 专线 |

> 向量检索（pgvector）对内存与 IO 敏感，知识库规模超过百万 chunk 时建议为 PostgreSQL 实例预留独立内存与 SSD。

## 5. 网络拓扑

- 接入区：Nginx/SLB，对外仅暴露 443。
- 应用区：app 实例，仅对中间件与医院集成区开放端口。
- 数据区：PostgreSQL/Redis/MinIO，仅应用区可访问，禁止直接外联。
- 集成区：经集成总线与院内 HIS/EMR/LIS/PACS 通信，白名单 + mTLS。
- 管理区：监控/日志/堡垒机，独立 VLAN，审计访问。

## 6. 端口规划

| 端口 | 服务 | 暴露范围 |
| --- | --- | --- |
| 443 | Nginx (HTTPS) | 院内终端/浏览器 |
| 8080 | app (Bun server) | 应用区内网 |
| 5432 | PostgreSQL | 应用区 |
| 6379 | Redis | 应用区 |
| 9000/9001 | MinIO API/Console | 应用区 |
| 9200 | 监控 Agent（如启用） | 管理区 |

## 7. 高可用架构

- **应用层**：≥2 实例，Nginx 健康检查剔除故障节点；无状态可随起随停。
- **数据层**：PostgreSQL 主从流复制 + 自动故障切换（Patroni/repmgr）；Redis 哨兵；MinIO 分布式纠删码。
- **接入层**：SLB 双节点，Nginx 主备（Keepalived + VIP）。
- **RTO** ≤ 30 分钟；**RPO** ≤ 5 分钟（生产集群目标）。

## 8. 容灾架构

- 同城双活/异地灾备：PostgreSQL WAL 归档异地同步；MinIO 跨站点复制。
- 定期恢复演练（见 [备份恢复手册](../operations/04-备份恢复手册.md)）。
- 关键依赖（HIS/EMR/LIS/PACS）不可用时降级为 Mock/只读模式，保障病历浏览与 CDS 可用。
