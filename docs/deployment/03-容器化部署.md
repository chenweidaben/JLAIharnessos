## 1. Dockerfile

基于官方 Bun 镜像，多阶段构建，控制镜像体积。

```dockerfile
# ---- 构建阶段 ----
FROM oven/bun:1.3 AS builder
WORKDIR /app
COPY package.json bun.lock ./
RUN bun install --frozen-lockfile
COPY . .
RUN bun run build

# ---- 运行阶段 ----
FROM oven/bun:1.3-slim
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./
EXPOSE 8080
USER bun
ENTRYPOINT ["bun", "dist/server.js"]
```

构建与推送：

```bash
docker build -t registry.jianlan.tech/medical/agent:1.0.0 .
docker push registry.jianlan.tech/medical/agent:1.0.0
```

## 2. docker-compose（单机/测试）

```yaml
version: "3.9"
services:
  app:
    image: registry.jianlan.tech/medical/agent:1.0.0
    ports: ["8080:8080"]
    env_file: .env
    depends_on: [postgres, redis, minio]
  postgres:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_DB: jianlan_agent
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes: ["pgdata:/var/lib/postgresql/data"]
  redis:
    image: redis:7
    command: ["redis-server", "--requirepass", "${REDIS_PASSWORD}"]
  minio:
    image: minio/minio
    command: ["server", "/data", "--console-address", ":9001"]
    volumes: ["miniodata:/data"]
volumes:
  pgdata: {}
  miniodata: {}
```

启动：`docker compose up -d`。

## 3. Kubernetes 部署清单

### 3.1 Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata: { name: jianlan-agent, namespace: medical }
spec:
  replicas: 2
  selector: { matchLabels: { app: jianlan-agent } }
  template:
    metadata: { labels: { app: jianlan-agent } }
    spec:
      containers:
        - name: agent
          image: registry.jianlan.tech/medical/agent:1.0.0
          ports: [{ containerPort: 8080 }]
          envFrom: [{ secretRef: { name: agent-secrets } }]
          readinessProbe: { httpGet: { path: /health, port: 8080 } }
          livenessProbe: { httpGet: { path: /health, port: 8080 }, initialDelaySeconds: 30 }
```

### 3.2 Service

```yaml
apiVersion: v1
kind: Service
metadata: { name: jianlan-agent, namespace: medical }
spec:
  selector: { app: jianlan-agent }
  ports: [{ port: 80, targetPort: 8080 }]
```

### 3.3 ConfigMap / Secret

- ConfigMap：非敏感配置（端口、日志级别、适配器开关）。
- Secret：`DATABASE_URL`、`REDIS_URL`、`MINIO_*`、`LLM_API_KEY`（加密存储，禁止明文入库）。

### 3.4 Ingress

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata: { name: jianlan-agent, namespace: medical }
spec:
  tls: [{ hosts: [agent.hospital.local], secretName: agent-tls }]
  rules:
    - host: agent.hospital.local
      http:
        paths:
          - path: /
            pathType: Prefix
            backend: { service: { name: jianlan-agent, port: { number: 80 } } }
```

## 4. Helm Chart

Chart 结构：

```
helm/jianlan-agent/
├── Chart.yaml
├── values.yaml          # 镜像/副本数/资源/集成适配器开关
├── templates/
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── configmap.yaml
│   ├── secret.yaml
│   └── ingress.yaml
```

安装：

```bash
helm install jianlan-agent ./helm/jianlan-agent -n medical --create-namespace \
  -f values.prod.yaml
```

升级：

```bash
helm upgrade jianlan-agent ./helm/jianlan-agent -f values.prod.yaml
```

## 5. 镜像构建与推送流水线

1. CI 执行 `typecheck → lint → test → build`；
2. 构建镜像并打双标签：`latest` 与 Git commit；
3. 推送至院内私有 Harbor；
4. CD 经 Helm 灰度发布，先 1 个副本观察，再全量。

## 6. 容器编排注意事项

- 应用无状态，会话外置 Redis，Pod 重建不丢失会话；
- PostgreSQL/Redis/MinIO 有状态服务建议用 Operator（CloudNativePG / Bitnami）或独立部署，不随应用 Helm 生命周期管理；
- 配置资源 requests/limits，避免 LLM 长连接 OOM；
- 日志输出到 stdout/stderr，由集群采集（见云原生部署）。
