# 健澜AI原生医院操作系统OS 重构 · 03-开发指南

> 本文档是 02-技术架构 的工程落地手册，面向 Java / Python / TypeScript 三端工程师。

## 1. 工程总览

### 1.1 仓库组织：多 repo，而非 Monorepo

推荐 **4 个独立仓库**，按语言/部署边界切分，避免 Monorepo 的 CI 耦合与权限混乱：

| 仓库 | 语言 | 内容 | 负责人 |
|---|---|---|---|
| `jianlan-java` | Java 21 / Maven | `gangos-trading` 模块化单体 + FHIR Server + medical-insurance | Java 组 |
| `jianlan-python` | Python 3.11 / Poetry | `ai-orchestrator` + `mcp-gateway` + vLLM 配置 | AI 组 |
| `jianlan-bff-web` | TS 5.5 / pnpm | `bff-aggregator` + `gangos-gateway` + 前端 React 19 | 前端组 |
| `jianlan-helm-charts` | Helm / YAML | k3s 离线 Chart、docker-compose 模板、install.sh | 运维组 |

**为什么不 Monorepo**：三语言 CI 镜像、发布节奏、招聘画像完全不同；Monorepo 会让一次前端改动触发 Java 全量构建。跨仓库共享契约（OpenAPI、事件 schema）通过 `jianlan-contracts` 子模块（git submodule）或独立 `contracts` 仓库版本化引用。

### 1.2 分支模型：Trunk-based + short-lived branch

- 主干 `main` 永远可发布； feature 分支存活 ≤3 天，PR 合并后即删。
- 发布分支 `release/x.y` 仅在生产打补丁时拉出。
- 禁止 long-lived develop 分支（避免 Git Flow 的合并地狱）。

### 2.2 Controller / Service / Repository 分层规则

```java
// ===== api/web/RegController.java =====
@RestController
@RequestMapping("/api/v1/reg/orders")
@RequiredArgsConstructor
public class RegController {

    private final RegApplicationService regAppService;

    @PostMapping
    @PreAuthorize("hasPermission('#cmd.deptCode','REG_BOOK')")
    public ApiResponse<BookVO> book(
            @RequestHeader("X-Request-Id") String requestId,
            @Valid @RequestBody BookCmd cmd) {
        BookVO vo = regAppService.book(cmd, requestId);
        return ApiResponse.ok(vo);
    }
}

// ===== domain/service/RegDomainService.java =====
@DomainService
@RequiredArgsConstructor
public class RegDomainService {
    private final RegOrderRepository repo;
    private final SourcePoolRepository sourcePool;

    @Transactional
    public RegOrder book(BookCmd cmd, String requestId) {
        // 1. 幂等检查
        RegOrder exist = repo.findByRequestId(requestId);
        if (exist != null) return exist;
        // 2. 领域规则：号源余量、限号、黑名单
        SourcePool pool = sourcePool.lockByScheduleId(cmd.scheduleId());
        if (!pool.remain(cmd.patientCount())) {
            throw new BizException(10001, "号源已约满");
        }
        // 3. 聚合根落库
        RegOrder order = RegOrder.create(cmd, requestId);
        repo.save(order);
        return order;
    }
}

// ===== RegApplicationService（api 层编排事务 + Outbox） =====
@Service
@RequiredArgsConstructor
public class RegApplicationService {
    private final RegDomainService domain;
    private final RegEventPublisher publisher;

    @Transactional
    public BookVO book(BookCmd cmd, String requestId) {
        RegOrder order = domain.book(cmd, requestId);
        publisher.publish(new RegOrderBookedEvent(order.getId(), order.getPatientId()));
        return BookVO.from(order);
    }
}
```

### 2.3 本地消息表实现模板

```java
// ===== shared/outbox/OutboxMessage.java =====
@Entity
@Table(name = "local_outbox", schema = "shared")
public class OutboxMessage {
    @Id
    @GeneratedValue
    private Long id;
    private String topic;
    private String payload;       // JSON
    private String traceparent;
    private String status = "PENDING";
    private int retryCount;
    private OffsetDateTime nextRetryAt;
    private OffsetDateTime createdAt;
}

// ===== shared/outbox/OutboxRelay.java =====
@Component
@RequiredArgsConstructor
@Slf4j
public class OutboxRelay {
    private final OutboxRepository outbox;
    private final KafkaTemplate<String, String> kafka;

    @Scheduled(fixedDelay = 1000)
    @Transactional
    public void relay() {
        List<OutboxMessage> batch = outbox.findTop100ByStatusOrderByNextRetryAtAsc("PENDING");
        for (OutboxMessage msg : batch) {
            try {
                kafka.send(msg.getTopic(), String.valueOf(msg.getId()), msg.getPayload())
                     .get(5, TimeUnit.SECONDS);
                msg.markSent();
            } catch (Exception e) {
                msg.increaseRetry();
                log.warn("outbox send failed id={} retry={}", msg.getId(), msg.getRetryCount(), e);
            }
        }
        outbox.flush();
    }
}
```

**要点**：业务事务内 `INSERT local_outbox` 与业务表同事务提交；Relay 单线程轮询，保证至少一次投递；消费端按 CloudEvents `id` 幂等。

### 2.4 MyBatis-Plus 写法 / 分页 / 多租户

```java
// ===== RegOrderMapper.java =====
@Mapper
public interface RegOrderMapper extends BaseMapper<RegOrderPO> {
    IPage<RegOrderPO> selectPage(Page<?> page, @Param("qo") RegQuery qo);
}

// ===== RegOrderServiceImpl.java =====
@Service
@RequiredArgsConstructor
public class RegOrderServiceImpl implements RegOrderRepository {
    private final RegOrderMapper mapper;

    @Override
    public IPage<RegOrder> queryPage(RegQuery qo, long page, long size) {
        Page<RegOrderPO> p = new Page<>(page, size);
        return mapper.selectPage(p, qo).map(this::toDomain);
    }
}
```

- **多租户**：TenantLineInnerInterceptor 自动在 SQL 追加 `tenant_id = ?`；忽略租户的查询（如 EMPI 跨院匹配）用 `@InterceptorIgnore(tenantLine = "true")`。
- **分页**：必须用 MyBatis-Plus `Page`，禁止手写 `LIMIT`（PG/达梦方言由插件处理）。
- **SQL 墙**：DruID 连接池开启 `wallfilter`，禁止 `SELECT *`、禁止无 WHERE 的 UPDATE/DELETE。
- **慢查询**：`log_min_duration_statement=200ms`，CI 要求新 SQL 必须附 `EXPLAIN ANALYZE` 计划截图。

### 3.3 vLLM 客户端封装（超时 8s + 信号量并发控制）

```python
import asyncio
from openai import AsyncOpenAI
from fastapi import HTTPException

class VLLMClient:
    def __init__(self, base_url: str, max_concurrency: int = 120):
        self._client = AsyncOpenAI(base_url=base_url, api_key="EMPTY")
        self._sem = asyncio.Semaphore(max_concurrency)

    async def chat(self, messages: list[dict], model: str = "Qwen2.5-72B-Instruct") -> str:
        if not self._sem.locked():
            pass
        async with self._sem:                       # 超过 120 路直接排队
            try:
                resp = await asyncio.wait_for(
                    self._client.chat.completions.create(
                        model=model,
                        messages=messages,
                        stream=False,
                        max_tokens=512,
                    ),
                    timeout=8.0,                     # 硬超时 8s，绝不 30s 干等
                )
                return resp.choices[0].message.content or ""
            except asyncio.TimeoutError:
                # 超时切规则引擎模板
                return self._fallback_template(messages)
            except Exception as e:
                raise HTTPException(status_code=503, detail="AI 通道繁忙，已切规则模板")

    def _fallback_template(self, messages):
        # 返回本地 50 种常见问诊场景模板
        return "【AI 加速通道排队中】以下为初步建议：请结合查体与检验结果……"
```

**要点**：
- 单 Pod `asyncio.Semaphore(120)`，2 节点合计 240 路；超过返回 429。
- 超时 **8s**（不是 30s），超时 cancel + 返回已生成部分或规则模板。
- 流式 SSE 输出：首 token <1.5s，医生边等边看。

### 4.4 traceId 透传（中间件）

```ts
// middleware/trace.ts
export async function traceMiddleware(c: any, next: any) {
  let parent = c.req.header("traceparent");
  if (!parent) {
    const traceId = crypto.randomUUID().replace(/-/g, "");
    const spanId = crypto.randomUUID().replace(/-/g, "").slice(0, 16);
    parent = `00-${traceId}-${spanId}-01`;
  }
  c.ctx.traceparent = parent;
  c.ctx.traceId = parent.split("-")[1];
  await next();
}
// 下游 fetch 自动注入
export async function httpc(url: string, opts: any, ctx: any) {
  return fetch(url, { ...opts, headers: { ...opts.headers, traceparent: ctx.traceparent } });
}
```

## 5. 数据库规范

### 5.1 命名

- 表名：`{模块前缀}_{实体}`，snake_case，如 `reg_order`、`charge_bill`、`emr_document_version`。
- schema 按模块：`emp` / `reg` / `charge` / `pharm` / `ord` / `nur` / `emr` / `cds` / `iam` / `term` / `fhir` / `ins` / `shared` / `ai`。
- 字段：snake_case；布尔用 `is_` / `has_` 前缀；时间用 `_at` 后缀。
- 索引：`idx_{表}_{列}`；唯一索引：`uk_{表}_{列}`。

### 5.2 主键

- 统一 **BIGINT 雪花 ID**（应用层生成，`IdWorker`），不依赖 DB 自增（达梦语法不同）。
- 事件 ID / 幂等键用 **UUIDv7**（可排序），不用 UUIDv4（无序导致索引页分裂）。

### 5.3 审计字段（所有表必带）

```sql
created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
created_by  BIGINT,
updated_by  BIGINT,
version     BIGINT NOT NULL DEFAULT 0,     -- 乐观锁
deleted     BOOLEAN NOT NULL DEFAULT FALSE  -- 软删
```

- MyBatis-Plus `MetaObjectHandler` 自动填充；`@Version` 乐观锁；`@TableLogic` 软删。
- 审计日志（谁在何时改了什么）入 `iam.audit_log`，留存 ≥6 个月。

### 5.4 索引规范

- 所有外键列必须有索引；高频 WHERE/ORDER BY 列组合建联合索引，最左前缀。
- 禁止在索引列上用函数（`WHERE DATE(create_time)=...` 改为范围查询）。
- 新 SQL 必须 `EXPLAIN ANALYZE` 验证 type=range/ref、rows 估算合理、无 filesort。
- 分区：挂号流水按月 RANGE；医嘱按科室哈希 8 表；审计日志按日分区（30 天 detach）。
- EMR 文档本体存 MinIO，PG 只存元数据 + content_hash。

### 5.5 变更管理

- Flyway 管理版本化 DDL：`V{date}__{desc}.sql`，禁止手工 `ALTER TABLE`。
- 大表 DDL 低峰执行 + `pg_repack` 在线操作。
- 敏感字段（姓名/身份证/手机）SM4 加密存储，查询用脱敏视图 `ai_v_*` 给 AI 节点。

## 6. CI/CD

### 6.1 流水线模板（GitLab CI / GitHub Actions 同构）

```yaml
# .gitlab-ci.yml（精简）
stages: [lint, test, build, image, deploy]

lint:
  stage: lint
  script:
    - mvn -B compile          # Java
    - ruff check .           # Python
    - eslint src/            # TS

test:
  stage: test
  services: [postgres:16, redis:7, kafka:3.7]
  script:
    - mvn -B verify          # Testcontainers
    - pytest -q
    - bun test && node --test

build:
  stage: build
  script:
    - mvn -B package -DskipTests
    - poetry build
    - pnpm build

image:
  stage: image
  script:
    - docker build -t harbor.local/gangos/trading:$CI_COMMIT_SHA .
    - docker push harbor.local/gangos/trading@sha256:...   # 固定 digest，禁 latest

deploy:
  stage: deploy
  script:
    - helm upgrade trading ./charts/trading -f values-prod.yaml --wait
  only: [main]
```

### 6.2 离线部署

- 医院内网无外网，所有交付物离线 tar 包：
  - k3s 二进制 + 镜像 tar（~2GB）；
  - Helm Chart tgz（APISIX/PG/Redis/Kafka/Loki/Prom/Jaeger）；
  - 基础镜像（`openjdk:21-slim` / `python:3.11-slim` / `bun:1-alpine`）`docker save`。
- 交付 `install.sh /media/usb/` 一键脚本；Harbor 内网仓库同步镜像。
- 镜像必须固定 digest（`image:tag@sha256:...`），禁止 `latest`。

### 6.3 发布与回滚

- 蓝绿/金丝雀：Helm values 切 1 个 Pod 观察 30 分钟，业务低峰（晚 22:00–次日 6:00）。
- 回滚：`helm rollback <release> <revision>`，1 分钟内完成；revision 保留 10 个。
- PR 模板必填"回滚命令"字段。

## 7. 代码评审 Checklist（10 条硬规则）

| # | 规则 | 拦截方式 |
|---|---|---|
| 1 | 新接口必须带 traceId（W3C traceparent 注入） | CI + Reviewer 检查 |
| 2 | 新 SQL 必须附 `EXPLAIN ANALYZE` 计划 | PR 模板必填 |
| 3 | AI 输出必须带 `adopted/modified/rejected` 反馈字段 | 缺字段禁上线 |
| 4 | BFF 行内 SQL / 直连 DB 数 = 0 | ESLint + grep 扫描 |
| 5 | 写接口必须有 `X-Request-Id` 幂等键 | Reviewer 检查 |
| 6 | 外部 HTTP 调用必须设超时（connect 2s / read 5s，医保 read 3s） | 模板代码强制 |
| 7 | 禁止 Seata AT / 禁止 Istio / 禁止境外 LLM API | 依赖扫描 |
| 8 | 病历写入必须走 append-only + 哈希链 + CA 签章 | 领域层封装 |
| 9 | 敏感字段日志必须脱敏（姓名/身份证/手机打码） | 日志中间件 + CI 正则扫描 |
| 10 | Pod 必须设 resources.requests=limits（CPU/内存），readinessProbe 必配 | Helm Chart 模板强制 |

## 9. 常见反模式（禁止）

1. **BFF 写业务规则/SQL** —— 必须下沉到 Java 域服务。
2. **跨模块直接 @Autowired 实现类** —— 走 api 接口 + 本地事件。
3. **AI 节点直连 PHI 生产库** —— 走脱敏视图 + NetworkPolicy。
4. **vLLM 超时 30s 干等** —— 8s 硬超时切规则模板。
5. **Seata AT 全局锁** —— 本地消息表 + Saga。
6. **K8s 一步到位 / Istio** —— 阶段 0/1 用 compose+systemd，阶段 2 才 k3s。
7. **PG-only 语法（RETURNING/JSONB 操作符）** —— 方言抽象，保 PG→达梦可迁移。
8. **缓存账单/已支付状态** —— 钱以 DB 为准。
9. **`SELECT *` / 索引列函数 / 深分页** —— SQL 墙拦截。
10. **镜像 latest / 手工 ALTER TABLE** —— digest + Flyway。
