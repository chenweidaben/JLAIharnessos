# 健澜杠OS 重构 · 专家论证决策基线 v1.0

> 本文档是 4 视角专家论证（首席架构师 / 医疗合规 / 性能运维 / 商业成本）的综合修正结论，
> 是后续 00-06 七份正式文档的**唯一事实来源**。所有正式文档与本文冲突时，以本文为准。
> 生成日期：2026-10-19

## 0. 一句话总纲

**原"12 个月全量重构到 Java+Python+TS 三层微服务 + K8s + Spring Cloud 全家桶"方案被否决，修正为"双轨并行 18-24 个月、模块化单体起步、合规与信创硬约束前置、AI 造血反哺重构"。**

---

## 1. 战略级修正（最关键，不可动摇）

### 1.1 双轨并行，不是单轨重构

| 轨道 | 内容 | 周期 | 目标 |
|---|---|---|---|
| **A 轨（造血）** | 保留现有 Bun+TS 单体 BFF，聚焦 AI 科室产品：病历质控、AI 导诊、CDS 辅助、护理看板 | 0-6 个月 | 签 3 家医院 POC / SaaS，产生首笔收入 |
| **B 轨（重构）** | Java 核心域模块化单体 → 绞杀者模式渐进替换 HIS/EMR 核心 | 6-24 个月 | 真实三甲生产环境落地 |

**理由（商业专家）**：12 个月全量重构 TCO 约 1800 万、期间零收入，而三甲 HIS 项目回款 18-36 个月，初创账上现金撑不到回款。必须用业务养技术，不能用融资养技术。

### 1.2 不直接替换 HIS，先打 AI 科室切入

三甲招标硬门槛通常要求"成立 ≥10 年、同类三甲案例 ≥5 个、等保三级、CMMI5"——初创公司连投标资格都没有。
A 轨产品定位为"AI 增值模块"，挂在医院现有 HIS 旁边跑（旁路模式），不碰主流程，先攒案例与合规资质。

### 1.3 可用性目标从 99.99% 下调到 99.95%

- 99.99% = 年停机 ≤52 分钟，对 <30 人团队是财务自杀
- **99.95% = 年停机 ≤4.3 小时**，主备同城 + Patroni 同步流复制可达
- 挂号 3000 QPS、P99 < 200ms 目标**保留且可达**

## 2. 架构演进路线（技术专家共识）

### 2.1 分阶段部署，不一步到位

| 阶段 | 时间窗 | 部署形态 | 适用客户数 |
|---|---|---|---|
| 阶段 0 | 0-90 天 | Docker Compose + systemd + Keepalived VIP（单机房 3 节点） | POC / 样板医院 |
| 阶段 1 | 90-180 天 | Docker Compose + systemd + 双机主备（Patroni） | 1-2 家生产 |
| 阶段 2 | 180 天+ | **k3s 1.30**（单二进制 + embedded etcd + 内置 Traefik）+ 全封装离线 Helm Chart | ≥3 家 |

**禁止**：原生 kubeadm K8s、Istio、任何 Service Mesh（12 个月内）。
理由：医院信息科 3-5 人（传统 Windows 运维背景）hold 不住；Istio sidecar 多吃 100-200ms P99，直接击穿 200ms 目标。

### 2.2 Java 核心：模块化单体起步，不 Day-1 上微服务

- **Phase 1（B 轨 0-6 月）**：Spring Boot 3.5.3 + **Spring Modulith 1.4**（Java 21），单进程多模块，跨模块走本地事件
- **Phase 2（B 轨 6-18 月）**：当第 3 个模块需要独立扩缩容时，才引入 **Spring Cloud Alibaba 2023.0.3 + Nacos 2.4**
- **持久层**：MyBatis-Plus（医疗 SQL 复杂，JPA 不合适；jOOQ 学习成本高）
- **分布式事务**：**本地消息表 + Spring StateMachine Saga**，直接平移现有 `src/bff/outboxRelay.ts` 与 `src/saga/` 雏形
- **明确禁止 Seata AT**：全局行锁在挂号高峰会把 `patient_id` 索引锁死，P99 秒级

### 2.3 AI 层：Python FastAPI + vLLM 本地部署

- FastAPI + Uvicorn（不用 Gunicorn），worker 数 = CPU 核数 × 2
- **vLLM 本地部署开源模型**（Qwen2.5-72B-Instruct / DeepSeek-V3 / GLM-4），**禁止调用 OpenAI / Claude / Gemini 等境外 API**（数据出境红线）
- 硬件：H20 96GB × 2 节点（或昇腾 910B × 2，信创路径）
- **并发现实**：单卡 7B AWQ 量化稳定并发仅 60-80 路，2 节点 128 路 + FastAPI 信号量排队
- **超时阈值 8s**（不是 30s），超时即切规则引擎模板，绝不让医生工作站干等
- Agent 框架：自研轻量编排 + MCP SDK（仓库已有 `@modelcontextprotocol/sdk 1.29`），不引 LangChain

### 2.4 BFF 层：Bun 保留但必须双运行时

- 代码必须同时通过 **Bun 1.4** 与 **Node.js 22 LTS** 测试
- 禁用 `bun:*` 特有模块
- **BFF 必须薄**：ESLint 规则强制 BFF 行内 SQL 数 = 0，禁止 route→repo→db 直连
- 部署侧选运行时（医院若已统一 Node 则用 Node，不绑定 Bun）

### 2.5 中间件选型最终表

| 组件 | 选型 | 版本 | 备选/信创替代 |
|---|---|---|---|
| 边缘网关 | APISIX | 3.9 | Nginx + Lua；国产化可换 Apache APISIX 国产发行版 |
| 服务注册 | Nacos | 2.4 | k8s Service（阶段 2 后） |
| 配置中心 | Nacos | 2.4 | - |
| 消息队列 | Kafka | 3.7 |  RabbitMQ（轻量场景） |
| 关系库 | PostgreSQL | 16 | **达梦 8**（信创，3-6 月迁移） |
| 缓存 | Redis | 7.2 哨兵 | Cluster（分片后） |
| 连接池 | PgBouncer | 1.22 transaction 模式 | 前置双层池 |
| 链路追踪 | OpenTelemetry | 1.x + Jaeger | - |
| 指标 | Prometheus + Grafana | - | - |
| 日志 | Loki + Promtail | - | ELK（已有则保留） |
| JDK | OpenJDK | 21 LTS（ZGenerational ZGC） | 毕昇 JDK（鲲鹏） |

### 2.6 服务划分与迁移批次

| 批次 | 服务/模块 | 语言 | 说明 |
|---|---|---|---|
| 第一批（B 轨 M1-M6） | patient-master（患者主索引）、registration（挂号）、outpatient-charge（门诊收费） | Java Modulith | 最高并发、最核心 |
| 第二批（M6-M12） | orders（医嘱）、pharmacy（药房）、nursing（护理） | Java Modulith → 独立部署 | - |
| 第三批（M12-M18） | emr-core（EMR 核心）、cds（临床决策支持） | Java Modulith | 等 FHIR/EMPI 成熟后 |
| AI 层（A 轨先行） | 病历质控、AI 导诊、辅助问诊、CDS 推荐 | Python FastAPI + vLLM | 旁路模式，不碰主流程 |
| BFF 层（始终） | 薄聚合、鉴权、路由 | TS (Bun/Node) | 禁止行内 SQL |
| 中台 | FHIR Server、EMPI、术语服务（ICD-10/LOINC） | Java | 互联互通四甲必配 |

## 3. 合规硬约束（医疗合规专家）

1. **AI 节点网络隔离**：Python/vLLM Pod 禁止直连生产 PHI（姓名/身份证/手机/住址）库，必须访问独立脱敏视图；NetworkPolicy 层硬隔离。违反《个人信息保护法》第 28、55 条。
2. **病历版本与篡改检测**：append-only 版本表 + 哈希链 + TSA 时间戳 + CA 签章验签。依据：《电子病历应用管理规范（国卫医发〔2017〕8 号）》第 13、17 条。
3. **FHIR Server + EMPI 独立部署**：Kafka/APISIX **不能**替代 ESB/FHIR Server。互联互通四甲要求 IHE PIX/PDQ/XDS/ATNA Profile 举证。
4. **国密改造**：SM2（签名）/SM3（摘要）/SM4（存储加密）全链路；TLS 替换为 GMSSL。依据：等保三级 8.2.2 +《密码法》第 27 条。
5. **禁止境外大模型 API**：vLLM 必须本地开源模型，出口流量加 URL 黑名单。依据：《数据安全法》第 31 条。
6. **等保三级**：三权分立、审计日志全量留存 ≥6 个月、入侵防范、恶意代码防范按 8.1-8.5 逐项映射。
7. **电子签名**：CA 证书在微服务间通过 mTLS + JWT 声明传递，签名验签服务独立部署。
8. **医保对接**：CHS 接口、医保电子凭证、DRG/DIP 分组器放在 `medical-insurance` 独立服务；结算对账异步化。
9. **SaMD 边界**：CDS 仅作"提示/建议"，最终医嘱必须医生确认——产品形态规避 II/III 类医疗器械注册。
10. **信创路线图**：PostgreSQL → 达梦 8（3-6 月）、x86 → 鲲鹏/麒麟（6-12 月）、vLLM → 昇腾 910B 适配（Q4）。

## 4. 性能与运维硬参数（SRE 专家）

### 4.1 容量基线（2000 床三甲）

| 服务 | 峰值 QPS | Pod 数 | CPU | 内存 | DB 连接（HikariCP） |
|---|---|---|---|---|---|
| registration（挂号） | 3000 | 6 | 4C | 8G | ≤15/实例 |
| outpatient-charge | 800 | 4 | 4C | 8G | ≤15/实例 |
| orders/pharmacy | 500 | 3 | 4C | 8G | ≤10/实例 |
| emr-core | 200 | 3 | 4C | 8G | ≤10/实例 |
| AI 问诊（vLLM 节点） | 200 并发 | 2 节点 GPU | 32C | 256G + 2×96G 显存 | 不直连业务库 |
| BFF | 5000 | 4 | 2C | 4G | 不直连业务库（HTTP 调用） |

PG 集群前置 **PgBouncer transaction 模式**（pool_size=50、max_db_connections=150），避免连接风暴。

### 4.2 JVM 关键参数

- GC：**ZGenerational ZGC**（不是 G1），目标 P99 停顿 < 1ms
- 堆：4C8G 容器堆定 4G（-Xms4g -Xmx4g）
- 冷启动：lazy-init + readiness initialDelay=30s + CronHPA 早 7:00 预热到 6 Pod；CRaC 二期再上

### 4.3 限流熔断降级矩阵（关键路径）

| 接口 | 限流阈值 | 熔断条件 | 降级行为 |
|---|---|---|---|
| 挂号提交 | 3000 QPS/集群 | 医保外呼 P99 > 1.5s | **先自费后追溯退费**（患者先挂号，医保异步结算） |
| 医保外呼 | 100 QPS/实例 | 错误率 > 50% 持续 10s | 熔断 30s，切降级通道 |
| AI 问诊 | 128 并发 | 排队 > 30 或单请求 > 8s | 切规则模板生成结构化建议 |
| 医生工作站登录 | 500 QPS | - | 仅缓存，不降级 |

### 4.4 高可用

- 主备同城，Patroni 同步流复制（**RPO=0、RTO ≤ 5min**）
- Redis 哨兵（1 主 2 从 3 哨兵）
- Kafka 3 Broker，min.insync.replicas=2，acks=all
- 不做双活（对 <30 人团队过度设计）

### 4.5 三语言可观测性

- 统一 traceId：OpenTelemetry SDK（Java / Python / TS 三语言 artifact）
- BFF 入口生成 traceparent，HTTP/gRPC 透传
- 日志统一 JSON，Loki 采集
- 告警 Alertmanager：CPU>80%、内存>85%、P99>300ms、5xx>1%、磁盘>80%、PG 主从延迟>1s

## 6. 宪法级硬约束清单（必须写进 00-架构宪法）

1. **禁第四语言**：除 Java 21 / Python 3.11 / TypeScript 5.5 外，禁止引入 Go/Rust/PHP 等
2. **禁 Seata AT**：分布式事务一律本地消息表 + Saga
3. **禁 Istio / Service Mesh**：12 个月内
4. **禁 Day-1 全微服务**：Java 侧 Spring Modulith 模块化单体起步
5. **禁境外大模型 API**：vLLM 必须本地部署
6. **AI 节点禁直连 PHI 生产库**：必须走脱敏视图
7. **BFF 禁行内 SQL**：ESLint 强制 0
8. **Bun 代码必须兼容 Node 22 LTS**：禁 `bun:*` 模块
9. **所有病历写入必须 append-only + 哈希链 + CA 签章**
10. **所有跨服务调用必须带 OpenTelemetry traceId**
11. **所有外呼医保/第三方必须熔断 + 降级预案**
12. **所有加密必须支持国密 SM2/SM3/SM4 切换**
13. **数据库方言必须抽象（JOOQ/MyBatis 方言层）**，保留 PG→达梦可迁移性
14. **AI 输出必须带"采纳/修改/拒绝"医生反馈闭环**，未采纳样本回流再训练
