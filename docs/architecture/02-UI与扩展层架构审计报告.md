### 1.2 渲染引擎架构（定制Ink）

Claude Code并未使用上游Ink，而是维护了一个**深度定制的Ink分叉**（`src/ink/`，98个文件），核心改造点包括：

#### 1.2.1 双缓冲渲染管线

```
React Reconciler → DOM Tree (dom.ts) → Yoga Layout → 前/后帧缓冲(Frame) → 差分输出(log-update) → 终端
```

**关键文件**：
- `src/ink/reconciler.ts` — React自定义渲染器，将React元素映射到终端DOM
- `src/ink/renderer.ts` — 帧渲染器，双缓冲（frontFrame/backFrame）差分渲染
- `src/ink/render-node-to-output.ts` — 节点到屏幕字符的渲染，支持滚动虚拟化
- `src/ink/output.ts` — 输出缓冲，含字符缓存（charCache）避免重复字形计算
- `src/ink/screen.ts` — 屏幕缓冲区，支持字符池/超链接池的世代重置
- `src/ink/log-update.ts` — 终端日志更新，计算帧间差异最小化输出

**渲染优化机制**（`renderer.ts:31-100`）：
- 跨帧复用Output对象，charCache持久化（大多数行不变）
- Yoga布局计算前返回空帧（getComputedHeight()为NaN）
- Alt-screen模式下强制height=terminalRows，防止越界渲染
- `prevFrameContaminated`标记：选择覆盖、清屏、强制重绘时跳过blit优化

#### 1.2.2 布局系统

基于Yoga的Flexbox布局，样式属性完整映射（`src/ink/styles.ts:55-404`）：

| 布局类别 | 支持属性 |
|---------|---------|
| 盒模型 | margin/padding（含X/Y/单边）、border（四边独立可见性/颜色/dim） |
| Flexbox | flexGrow/flexShrink/flexBasis/flexDirection/flexWrap/alignItems/alignSelf/justifyContent |
| 尺寸 | width/height/minWidth/minHeight/maxWidth/maxHeight（支持数字和百分比） |
| 定位 | position(absolute/relative)、top/bottom/left/right |
| 溢出 | overflow/overflowX/overflowY（visible/hidden/scroll） |
| 间隙 | gap/columnGap/rowGap |
| 文本 | textWrap（wrap/wrap-trim/end/middle/truncate-*等8种） |
| 扩展 | opaque（不透明覆盖）、noSelect（文本选择排除）、borderText（边框标题） |

#### 1.2.3 颜色与样式系统

**颜色类型体系**（`src/ink/styles.ts:15-37`）：
- `RGBColor` — `rgb(r,g,b)` 精确颜色
- `HexColor` — `#rrggbb` 十六进制
- `Ansi256Color` — `ansi256(n)` 256色
- `AnsiColor` — 16种ANSI基础色（含bright变体）

**文本样式**（`TextStyles`）：color、backgroundColor、dim、bold、italic、underline、strikethrough、inverse

### 1.5 主题/样式管理

#### 1.5.1 主题定义体系

**主题名称**（`src/utils/theme.ts:91-98`）：
```
dark, light, light-daltonized, dark-daltonized, light-ansi, dark-ansi
```
外加 `auto`（跟随终端系统主题，通过OSC 11查询）。

**Theme类型**（`src/utils/theme.ts:4-89`）定义了**80+语义化颜色令牌**，分类如下：

| 类别 | 令牌示例 | 数量 |
|-----|---------|------|
| 品牌/角色色 | claude, claudeShimmer, permission, planMode, ide | 6 |
| 基础文本 | text, inverseText, inactive, subtle, suggestion, remember | 6 |
| 背景 | background, userMessageBackground, selectionBg, bashMessageBackgroundColor | 5 |
| 语义状态 | success, error, warning, merged, autoAccept | 5 |
| Diff | diffAdded, diffRemoved, diffAddedWord, diffRemovedWord（含dimmed） | 8 |
| 子代理颜色 | red/blue/green/yellow/purple/orange/pink/cyan（_FOR_SUBAGENTS_ONLY） | 8 |
| 彩虹高亮 | rainbow_red/orange/yellow/green/blue/indigo/violet（含shimmer） | 14 |
| TUI V2 | clawd_body, clawd_background, messageActionsBackground | 3 |
| 其他 | fastMode, briefLabelYou, briefLabelClaude, rate_limit_fill/empty, chromeYellow, professionalBlue | 8 |

#### 1.5.2 主题解析流程

```
用户配置(theme: 'auto'|'dark'|...) 
  → ThemeProvider (src/components/design-system/ThemeProvider.tsx)
    → activeSetting = previewTheme ?? themeSetting
    → if 'auto': systemTheme (OSC 11 watcher via terminal-querier)
    → currentTheme: ThemeName（已解析，非'auto'）
      → color() 函数 (src/components/design-system/color.ts)
        → 主题键查找: getTheme(theme)[key]
        → 原始颜色直传: rgb()/#hex/ansi256()/ansi:
        → colorize() (src/ink/colorize.ts) → ANSI转义序列
```

**主题预览机制**：ThemeProvider支持`setPreviewTheme`临时预览，`savePreview`保存，`cancelPreview`取消——用于`/theme`命令的实时预览。

#### 3.1.1 输入事件来源

#### 3.1.3 键位解析流程

```
用户按键 → Ink useInput回调
  ↓
buildKeystroke(input, key) → ParsedKeystroke
  ↓
resolveKey(input, key, activeContexts, bindings)
  ├── Phase 1: 单键匹配（遍历所有bindings，chord.length===1）
  │   ├── 上下文过滤（ctxSet.has(binding.context)）
  │   ├── matchesBinding精确匹配
  │   └── 最后一个匹配胜出（用户覆盖默认）
  ├── Phase 2: Chord匹配（如"ctrl+k ctrl+s"）
  │   ├── chord_started → 等待下一键
  │   ├── chord_cancelled → 超时/不匹配取消
  │   └── match → 执行action
  ├── unbound → 用户显式解绑（action===null）
  └── none → 无匹配，作为文本输入
```

**关键设计**（`resolver.ts:32-61`）：
- 纯函数，无状态无副作用
- `activeContexts`为数组（如`['Chat', 'Global']`），多上下文同时活跃
- 最后一个匹配胜出，实现用户绑定覆盖默认绑定
- `null` action表示显式解绑，吞掉事件

### 3.4 焦点管理

焦点管理通过**上下文栈**实现，而非传统的焦点元素追踪：

1. **KeybindingContext**维护一个活跃上下文数组
2. 对话框/面板打开时push上下文，关闭时pop
3. 键位解析时遍历所有活跃上下文，按优先级匹配
4. `useKeybinding` Hook允许组件动态注册/注销快捷键

这种设计避免了DOM焦点管理的复杂性，适合终端UI的模态交互模式。

### 4.1 命令类型体系

定义于`src/types/command.ts`，三种命令类型：

| 类型 | 标识 | 执行方式 | 典型用途 |
|-----|------|---------|---------|
| **Prompt命令** | `type: 'prompt'` | 生成prompt内容，发送给AI模型 | 技能/Skill类命令，如`/review`、`/commit` |
| **Local命令** | `type: 'local'` | 本地执行，返回文本结果 | 简单操作，如`/clear`、`/cost` |
| **Local-JSX命令** | `type: 'local-jsx'` | 本地执行，返回React组件 | 交互式UI，如`/help`、`/model`、`/plugin` |

**Command基础字段**：
```typescript
{
  name: string              // 命令名（斜杠后内容）
  description: string       // 描述（/help显示）
  aliases?: string[]        // 别名
  source: SettingSource | 'builtin' | 'mcp' | 'plugin' | 'bundled'
  isEnabled?: () => boolean // 启用条件
  isHidden?: boolean        // 是否在/help中隐藏
  userInvocable?: boolean   // 用户可直接调用
}
```

**Prompt命令特有**：`getPromptForCommand(args, context)` → `ContentBlockParam[]`，`progressMessage`，`allowedTools`，`model`，`context`('inline'|'fork')，`agent`，`effort`

**Local-JSX命令特有**：`load()` → `{ call(onDone, context, args): Promise<React.ReactNode> }`，懒加载

### 4.2 命令注册与解析流程

```
启动时:
  commands.ts → COMMANDS = memoize(() => [...90+内置命令...])
  + getSkillDirCommands(cwd)      — 用户技能目录

  slashCommandParsing.ts → 解析命令名和参数
  → 查找命令（name匹配，别名匹配）
  → 类型分发:
    ├── prompt → getPromptForCommand() → 生成ContentBlock → 注入消息 → query()
    ├── local → load().call() → LocalCommandResult(text/compact/skip)
    └── local-jsx → load().call(onDone, context, args) → 渲染React组件
```

### 5.3 桥接消息协议

#### 5.3.1 SDK消息类型（agentSdkTypes.ts）

桥接使用**SDK消息协议**，基于WebSocket的JSON消息，核心类型：

| 消息类型 | 方向 | 用途 |
|---------|------|------|
| `user` | 入站 | 用户消息 |
| `assistant` | 出站 | 助手响应 |
| `system` | 双向 | 系统消息（含local_command子类型） |
| `control_request` | 入站 | 控制请求（权限请求等） |
| `control_response` | 出站 | 控制响应 |
| `result` | 出站 | 执行结果 |
| `stdout` | 出站 | 标准输出（Direct Connect模式） |

**消息过滤**（`bridgeMessaging.ts:77-88`）：仅`user`、`assistant`、`system(local_command)`类型消息转发到桥接，工具结果/进度等内部消息不转发。虚拟消息（`isVirtual`）也被过滤。

#### 5.3.2 控制请求/响应协议

```typescript
// 控制请求（IDE → CLI）
SDKControlRequest = {
  type: 'control_request',
  request_id: string,      // UUID
  request: {
    type: string,          // 'permission' | 'input' | ...
    payload: unknown
  }
}

// 控制响应（CLI → IDE）
SDKControlResponse = {
  type: 'control_response',
  request_id: string,      // 对应请求ID
  response: unknown
}
```

**权限请求桥接**（`bridgePermissionCallbacks.ts`）：当CLI需要用户确认工具执行权限时，通过`control_request`发送到IDE，IDE展示确认UI，用户操作后通过`control_response`返回。

#### 5.3.3 ReplBridgeHandle接口

```typescript
type ReplBridgeHandle = {
  bridgeSessionId: string
  environmentId: string
  sessionIngressUrl: string
  writeMessages(messages: Message[]): void       // 写消息到桥接
  writeSdkMessages(messages: SDKMessage[]): void  // 写SDK消息
  sendControlRequest(request: SDKControlRequest): void
  sendControlResponse(response: SDKControlResponse): void
  sendControlCancelRequest(requestId: string): void
  sendResult(): void
  teardown(): Promise<void>
}
```

### 5.4 传输层

#### 5.4.1 V1/V2传输

`replBridgeTransport.ts`定义了两种传输：
- **V1传输**（`createV1ReplTransport`）：传统轮询+WebSocket混合
- **V2传输**（`createV2ReplTransport`）：CCRv2 SDK URL，改进的WebSocket协议

`HybridTransport`（`src/cli/transports/HybridTransport.ts`）支持传输层混合。

#### 5.4.2 Direct Connect模式

`src/server/directConnectManager.ts`实现直连模式：
- 基于WebSocket的直接连接（不经过云桥接）
- `DirectConnectConfig`：serverUrl/sessionId/wsUrl/authToken
- 回调：onMessage/onPermissionRequest/onConnected/onDisconnected/onError
- 支持NDJSON格式（多行JSON，每行一条消息）

### 5.5 桥接状态机

```
ready → connected → reconnecting → connected
                ↘ failed
```

状态定义于`replBridge.ts:83`：`'ready' | 'connected' | 'reconnecting' | 'failed'`

**重连机制**：
- `capacityWake.ts` — 容量唤醒，服务端通知客户端有新消息
- `flushGate.ts` — 刷新人控，控制消息刷新时机
- 指数退避重连（pollConfig配置间隔）

### 5.6 桥接初始化参数（BridgeCoreParams）

`replBridge.ts:91-148`定义了桥接初始化的完整参数，采用**依赖注入**设计：

| 参数 | 用途 |
|-----|------|
| dir/machineName/branch/gitRepoUrl | 环境信息 |
| title | 会话标题 |
| baseUrl/sessionIngressUrl | 服务端点 |
| workerType | 工作器类型（CLI/daemon） |
| getAccessToken | OAuth令牌获取 |
| createSession | 会话创建（REPL/daemon注入不同实现） |
| archiveSession | 会话归档 |
| toSDKMessages | 消息转换（Message[] → SDKMessage[]） |

这种注入设计使得桥接核心可在REPL和daemon（Agent SDK）两种环境中复用。

### 8.7 数据安全与权限适配

医疗场景必须满足《数据安全法》《个人信息保护法》《医疗卫生机构网络安全管理办法》：

1. **终端数据脱敏**：消息渲染时对患者姓名/身份证/手机号进行脱敏显示（可授权查看）
2. **操作审计**：所有医疗操作（查询/开单/修改）记录审计日志，包含操作人/时间/内容
3. **权限分级**：基于RBAC的细粒度权限（科室级/患者级/操作级），与HIS权限体系打通
4. **会话隔离**：不同患者的对话会话严格隔离，切换患者时清空上下文
5. **数据不落地**：终端不持久化患者敏感数据，会话结束后安全擦除
6. **传输加密**：所有桥接通信使用TLS 1.3+，符合医疗数据传输标准
