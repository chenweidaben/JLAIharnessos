### 1.3 核心设计模式



| 设计模式                   | 应用位置                                                 | 说明                                                       |
| ---------------------- | ---------------------------------------------------- | -------------------------------------------------------- |
| **Async Generator**    | `query()`、`QueryEngine.submitMessage()`、`runTools()` | 整个 Agent 循环基于异步生成器，实现流式输出与中断控制                           |
| **Feature Flag (DCE)** | `feature('XXX')` + `bun:bundle`                      | 编译期死代码消除，Ant-only 功能不进入外部构建                              |
| **Builder Pattern**    | `buildTool()` (`Tool.ts:783`)                        | 工具定义填充默认值，统一工具接口                                         |
| **Context Object**     | `ToolUseContext` (`Tool.ts:158`)                     | 工具执行上下文，贯穿整个调用链                                          |
| **Store Pattern**      | `AppStateStore` (`state/store.ts`)                   | 外部状态存储 + React `useSyncExternalStore` 绑定                 |
| **Strategy Pattern**   | `getAPIProvider()`                                   | 多模型提供商切换（Anthropic/Bedrock/Vertex）                       |
| **Pipeline Pattern**   | query.ts 上下文处理链                                      | Snip → Microcompact → ContextCollapse → Autocompact 四级压缩 |

### 2.4 交互式 REPL 模式 vs SDK 模式



| 维度    | REPL 模式 (main.tsx)                   | SDK 模式 (QueryEngine)                 |

| 上下文压缩 | 完整四级流水线 + UI 折叠视图                    | 四级流水线，compact\_boundary 后释放内存        |

### 3.2 工具并发执行策略

**文件**：`src/services/tools/toolOrchestration.ts:91`

`partitionToolCalls()` 函数将工具调用按**并发安全性**分区：



```
工具调用列表 \[T1, T2, T3, T4, T5]

&#x20;      │

&#x20;      ▼

partitionToolCalls()

&#x20;      │

&#x20;      ├─ T1: isConcurrencySafe=true  → 加入当前并发组

&#x20;      ├─ T2: isConcurrencySafe=true  → 加入当前并发组

&#x20;      ├─ T3: isConcurrencySafe=false → 关闭并发组，新建串行组 \[T3]

&#x20;      ├─ T4: isConcurrencySafe=false → 新建串行组 \[T4]

&#x20;      └─ T5: isConcurrencySafe=true  → 新建并发组 \[T5]

&#x20;      │

&#x20;      ▼

批次列表: \[{并发:\[T1,T2]}, {串行:\[T3]}, {串行:\[T4]}, {并发:\[T5]}]
```



* **并发组**：所有工具标记为 `isConcurrencySafe=true`（通常是只读工具如 Read、Glob、Grep），最大并发数由 `CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY` 控制（默认 10）

* **串行组**：包含写操作或有副作用的工具，逐个执行，前一个的 `contextModifier` 会影响后一个

* **默认值**：`buildTool()` 中 `isConcurrencySafe` 默认为 `false`（`Tool.ts:759`），即默认串行执行

### 3.3 StreamingToolExecutor 流式工具执行

**文件**：`src/services/tools/StreamingToolExecutor.ts`

在 API 流式响应过程中，工具调用块是**逐块到达**的。`StreamingToolExecutor` 实现了工具的**注册 - 执行 - 结果收集**异步流水线：



1. **注册阶段**：每个 `tool_use` content\_block 到达时立即调用 `addTool(block, assistantMessage)`

2. **执行阶段**：工具在后台异步执行，不阻塞 API 流的继续接收

3. **收集阶段**：`getCompletedResults()` 返回已完成的工具结果，在 API 流结束后统一处理

这种设计使得**工具执行与 API 流式接收并行**，显著降低了多工具调用场景的总延迟。

```
&#x20;   │   ├── name: 显示名称

&#x20;   │   ├── description: 技能描述

&#x20;   │   ├── when\_to\_use: 使用时机提示
```

#### 4.6.2 技能加载机制



```
技能加载流水线 (getSkillDirCommands, loadSkillsDir.ts:638)

│

├─ 加载源 (并行)

│   ├─ managedSkillsDir   → \~/.claude/skills (策略管理)

│   ├─ userSkillsDir      → \~/.claude/skills (用户级)
```

#### 4.6.3 技能执行流程

技能通过 `SkillTool` 工具执行：



1. LLM 调用 `SkillTool`，传入 `skill_name` 和参数

2. `SkillTool.call()` 查找技能定义，调用 `getPromptForCommand(args, context)`

3. `getPromptForCommand()` 执行参数替换、`${CLAUDE_SKILL_DIR}` 替换、内联 Shell 执行

4. 生成的内容作为用户消息注入当前对话

5. 如果 `context: 'fork'`，则在独立子代理中执行

6. 如果 `disable-model-invocation: true`，则仅输出内容不触发模型调用

### 4.8 权限控制系统 (Permission Control)

#### 4.8.1 权限架构

**文件**：`src/utils/permissions/` (20+ 文件)

权限系统采用**多层决策链**设计：



```
工具调用权限决策链 (canUseTool)

│

├─ 第1层: 工具级校验

│   └─ tool.validateInput(input, context)

│       └─ 工具自定义参数校验 (如文件路径合法性)

│

├─ 第2层: 工具级权限

│   └─ tool.checkPermissions(input, context)

│       └─ 工具特定权限逻辑 (如 Bash 命令危险模式检测)

│

├─ 第3层: 通用权限规则

│   ├─ alwaysAllowRules → 始终允许的规则

│   ├─ alwaysDenyRules  → 始终拒绝的规则

│   ├─ alwaysAskRules   → 始终询问的规则

│   └─ PermissionRule 解析 (permissionRuleParser.ts)

│       └─ 支持 "Bash(git \*)" 格式的工具+参数匹配

│

├─ 第4层: 自动模式安全分类器 (TRANSCRIPT\_CLASSIFIER)

│   ├─ bashClassifier.ts → Bash 命令危险分类

│   ├─ dangerousPatterns.ts → 危险模式库

│   └─ classifierDecision.ts → 分类决策逻辑

│

├─ 第5层: Hooks 拦截

│   ├─ PreToolUse hook → 工具执行前钩子

│   └─ PostToolUse hook → 工具执行后钩子

│

├─ 第6层: 用户确认 (交互式)

│   ├─ PermissionPrompt → 权限确认对话框

│   ├─ permissionExplainer.ts → 权限解释

│   └─ bypassPermissionsMode → 绕过权限模式 (--dangerously-skip-permissions)

│

└─ 决策结果: PermissionResult

&#x20;   ├─ { behavior: 'allow', updatedInput }     → 允许

&#x20;   ├─ { behavior: 'deny', reason }             → 拒绝

&#x20;   ├─ { behavior: 'ask', ... }                 → 询问用户

&#x20;   └─ { behavior: 'allowAfterEdit', updatedInput } → 编辑后允许
```
