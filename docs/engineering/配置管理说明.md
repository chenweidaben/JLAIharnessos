# 配置管理说明

> 版本：v1.0 · 日期：2026-09-16

## 1. 分层设计

```
config/
├── types.ts           # 配置类型定义
├── default.ts         # 所有环境的基线
├── development.ts     # 开发环境覆盖
├── test.ts            # 测试环境覆盖（全部走 Mock）
├── production.ts      # 生产环境硬约束
└── index.ts           # 按 NODE_ENV 合并

src/config/ConfigManager.ts   # 运行期单例 + zod 校验 + 热更新
.env.example                  # 环境变量模板
```

## 2. 合并优先级

从低到高：

1. `config/default.ts`
2. `config/<env>.ts`
3. 进程环境变量（`process.env.LLM_API_KEY` 等，见 `ConfigManager.applyEnvOverrides`）

## 3. 在代码中读取

```typescript
import { ConfigManager } from '@/config/ConfigManager';

const config = ConfigManager.getInstance().get();
console.log(config.llm.model);
```

## 4. 运行期校验

`ConfigManager` 内部使用 `zod` 对最终配置做 `safeParse`：

- 必填字段缺失或类型错误 → 启动即抛错
- `temperature` 限制在 0~2
- `httpPort` 限制 1~65535
- `healthCheckPath` 必须以 `/` 开头
- `auditRetentionDays` 不小于 30 天（等保三级要求）

## 5. 热更新（开发环境）

```typescript
ConfigManager.getInstance().reload();
```

会重新读取环境变量、再次校验，并记录「哪些 key 变了」到审计通道。

## 6. 密钥管理

- 仓库中只允许出现占位符（`.env.example`）
- 生产环境密钥由 KMS / 配置中心下发，**禁止硬编码**
- `ConfigManager.setAuditSink(...)` 可注入审计通道，记录配置变更

## 7. 新增配置项

1. 在 `config/types.ts` 增加字段
2. 在 `config/default.ts` 给默认值
3. 必要时在各环境覆盖文件中调整
4. 如来自环境变量，在 `ConfigManager.applyEnvOverrides` 中补充映射
5. 同步更新 `.env.example`
