# 监控告警说明

> 版本：v1.0 · 日期：2026-09-16

## 1. 模块组成

```
src/core/monitoring/
├── ErrorMonitor.ts        # 全局错误捕获 + 聚合 + 上报
├── PerformanceMonitor.ts  # 耗时埋点 + 分位数 + 告警
├── HealthChecker.ts       # 系统 / 依赖 / 适配器健康检查
└── index.ts
```

## 2. ErrorMonitor

### 2.1 全局兜底

构造时默认 `attachGlobalHandlers: true`，自动监听：

- `uncaughtException`
- `unhandledRejection`

### 2.2 错误聚合

相同指纹（错误名 + 前 3 行堆栈）在 60 秒窗口内计数，达到 `threshold` 才上报一次，避免告警风暴。

### 2.3 接入 Sentry / 自建

```typescript
const monitor = new ErrorMonitor({
  threshold: 1,
  reporter: {
    report: async (report) => {
      // 调 Sentry.captureException 或自建上报接口
    },
  },
});

// 业务代码
try {
  await something();
} catch (err) {
  monitor.capture(err, { context: { userId, patientId, operation: 'queryPatient' } });
}
```

## 3. PerformanceMonitor

### 3.1 埋点

```typescript
import { performanceMonitor } from '@core/monitoring';

performanceMonitor.record({
  name: 'his.queryPatient',
  durationMs: 120,
  at: Date.now(),
});

// 或包裹异步函数
await performanceMonitor.track('llm.call', () => llm.call(), 5000);
```

### 3.2 告警

默认阈值 5000ms，超时即触发 `onAlert` 监听器，并写入 `[perf-alert]` 警告日志。

### 3.3 分位数

```typescript
performanceMonitor.percentile('his.queryPatient', 95); // P95
performanceMonitor.summary(); // 所有指标的 P50/P95/P99/count
```

## 4. HealthChecker

### 4.1 注册探针

```typescript
const hc = new HealthChecker({ version: '0.1.0' });
hc.registerProbe({ name: 'his', check: () => hisAdapter.ping(), timeoutMs: 2000 });
hc.registerProbe({ name: 'emr', check: () => emrAdapter.ping() });
```

### 4.2 暴露 /health

```typescript
const report = await hc.check();
// 返回 { status: 'healthy' | 'degraded' | 'unhealthy', items: [...] }
```

建议在 HTTP Server 入口挂载 `GET /health`，返回该 JSON。

### 4.3 系统级检查

自动检查：

- 堆内存（默认 512MB 警告，1.5 倍不健康）
- 系统 load / CPU 核数

## 5. 告警通道

当前内置：

- 日志告警（写入 `[perf-alert]` / `[error]`）
- `ErrorMonitor.reporter` 钩子

生产部署时建议：

1. `reporter` 接到 Sentry / 自建错误中心
2. `HealthChecker` 报告接到 Prometheus / Grafana
3. 关键指标（P95 响应时间、错误率）接入值班群机器人
