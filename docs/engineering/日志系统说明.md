# 日志系统使用说明

> 版本：v1.0 · 日期：2026-09-16

## 1. 模块组成

```
src/core/logging/
├── types.ts            # LogLevel / LogEntry / LogTransport
├── Logger.ts           # 主入口，支持子 Logger、动态级别、耗时追踪
├── LogFormatter.ts     # JSON / 控制台彩色输出 + 自动脱敏
├── LogTransport.ts     # Console / File（轮转）/ Remote（批量缓冲）
└── index.ts            # 统一导出
```

零额外依赖，仅使用 `node:fs` / `node:os` / `node:path`。

## 2. 快速开始

```typescript
import { Logger, FileTransport } from '@core/logging';

const logger = new Logger({
  name: 'medical-tools/patient',
  transports: [
    // 默认已有控制台传输，这里再加文件传输
    new FileTransport({ dir: './logs', maxSizeBytes: 10 * 1024 * 1024, maxFiles: 14 }),
  ],
});

logger.info('查询患者', { patientId: 'P001' });
logger.error('HIS 调用失败', { code: 'TIMEOUT' });
```

## 3. 业务上下文

通过 `child()` 继承上下文字段，避免每次重复传：

```typescript
const reqLogger = logger.child({ requestId, sessionId, userId, patientId });
reqLogger.info('进入诊疗流程');
```

控制台输出会自动把这些字段拼成 `[req=xxx ses=xxx uid=xxx pt=xxx]`。

## 4. 日志级别

| 级别 | 用途 |
| --- | --- |
| DEBUG | 调试细节，生产关闭 |
| INFO | 关键业务节点 |
| WARN | 可恢复的异常 / 降级 |
| ERROR | 业务失败，需要关注 |
| CRITICAL | 全局崩溃 / 数据安全事件 |

运行期动态调整：`logger.setLevel('WARN')` 或 `Logger.setGlobalLevel(...)`。

## 5. 性能计时

```typescript
const end = logger.time('llm_call');
await llm.call();
end(); // 自动输出 [perf] llm_call { durationMs: ... }
```

## 6. 自动脱敏

`LogFormatter.desensitize` 在序列化前自动处理：

- 字段名匹配（`idCard` / `phone` / `name` / `address` / `token` / `apiKey` 等）
- 字符串中疑似身份证、手机号的正则替换

业务侧无需手动脱敏，但仍需遵守：**不要把原始患者数据塞进 fields**。

## 7. 文件轮转

`FileTransport` 行为：

- 当前文件 `app.log` 写满 `maxSizeBytes` 后改名 `app.log.1`
- 历史文件滚动为 `.2`、`.3` ...
- 超出 `maxFiles` 自动删除最老的文件

## 8. 远程上报

`RemoteTransport` 提供批量缓冲：

```typescript
new RemoteTransport({
  batchSize: 50,
  maxBuffer: 1000,
  sender: async (batch) => await loki.push(batch),
});
```

对接 ELK / Loki / Sentry 时实现 `sender` 即可。
