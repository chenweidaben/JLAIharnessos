## 1. Agent 体系架构

### 1.1 设计原则

健澜科技数智医院智能体的 Agent 体系遵循以下核心设计原则：



1. **AI 辅助、人工决策**：所有 Agent 定位为临床决策支持工具，最终诊疗判断始终由具备资质的医务人员做出

2. **分层解耦、各司其职**：按诊疗、管理、赋能、平台四层划分，每层 Agent 职责边界清晰

3. **工具驱动、可观测**：每个 Agent 的能力通过调用医疗工具实现，所有调用可审计、可追溯

4. **风险分级、权限最小化**：按操作风险等级（low/medium/high）实施差异化确认与审核机制

5. **可扩展、可配置**：支持医院 / 科室自定义新增 Agent，无需修改核心引擎代码

### 1.3 L1 诊疗智能体详细设计

#### AG-01：ADS 病历书写智能体



| 项目         | 内容                                                                                                                                                                            |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **智能体名称**  | ADS 无感病历书写智能体（Auto Documentation System）                                                                                                                                      |
| **职责描述**   | 将医生问诊 / 查房的语音对话、上传的检查报告和既往资料，自动转化为结构化医学文书草稿，支持 72 种医学文书类型                                                                                                                     |
| **触发条件**   | ①医生在工作台点击 "ADS 录音转写" 或语音唤醒；②诊疗场景自动激活；③医生上传病历资料后触发生成                                                                                                                           |
| **输入**     | ①实时音频流（门诊 / 查房 / 会诊录音）②上传的检查报告 / 照片 / 既往病历 ③患者基本信息 ④选择的病历类型（72 种之一）⑤科室 / 病种模板                                                                                                 |
| **输出**     | ①结构化病历草稿（按所选文书类型模板）②转写文本全文 ③缺失信息提示清单 ④音频文件留存引用                                                                                                                                |
| **调用工具列表** | `asr_transcribe`（语音转写）、`get_medical_template`（获取病历模板）、`generate_medical_record`（AI 生成病历初稿）、`get_patient_detail`（患者详情）、`get_patient_history`（就诊历史）、`medical_record_qa`（病历质量预检） |
| **权限要求**   | 需`emr:write`（病历书写）、`patient:read`（患者读取）权限；录音文件需`audio:record`权限                                                                                                               |
| **风险等级**   | medium（生成草稿需医生确认后归档）                                                                                                                                                          |
| **协作关系**   | 输出供 AG-07 病历质控智能体检阅；生成的病历归档后供 AG-20 患者时间线智能体归集                                                                                                                                |

#### AG-02：问诊引导智能体



| 项目         | 内容                                                                                                    |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| **智能体名称**  | 智能问诊引导智能体                                                                                             |
| **职责描述**   | 根据当前科室、患者主诉和已采集信息，动态生成建议追问问题，帮助医生规范问诊、避免遗漏关键信息                                                        |
| **触发条件**   | ①ADS 录音转写过程中自动激活；②医生手动点击 "问诊引导"；③选择科室 / 病种模板后自动推荐问诊框架                                                 |
| **输入**     | ①患者主诉 / 现病史片段 ②科室 / 病种信息 ③已有的病历资料 ④知识库中的问诊框架 / 技能                                                     |
| **输出**     | ①建议追问问题列表（按优先级排序）②问诊完整性评估 ③推荐的病例模板                                                                    |
| **调用工具列表** | `get_medical_template`（获取模板）、`query_patient`（患者查询）、`diagnosis_suggestion`（诊断建议，用于追问方向）、知识管理智能体 RAG 检索 |
| **权限要求**   | 需`patient:read`权限；仅提供建议，不直接修改病历                                                                       |
| **风险等级**   | low（纯建议提示）                                                                                            |
| **协作关系**   | 与 AG-01 ADS 协同，在问诊过程中实时提供追问建议；追问结果反馈给 AG-01 用于病历生成                                                    |

#### AG-03：循证诊断智能体



| 项目         | 内容                                                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **智能体名称**  | 循证诊断智能体（含鉴别诊断分析器）                                                                                                            |
| **职责描述**   | 基于患者病史、查体和检查结果，提供诊断建议和鉴别诊断分析，呈现支持与不支持的证据，帮助医生进行复核与判断                                                                         |
| **触发条件**   | ①病历形成后医生主动调用；②诊疗场景中通过自然语言提问触发（如 "帮我分析一下这个病例"）                                                                                |
| **输入**     | ①患者病史（主诉 / 现病史 / 既往史）②体格检查结果 ③检验检查报告 ④影像学资料 ⑤相关指南 / 文献（知识库）                                                                  |
| **输出**     | ①可能诊断列表（按可能性排序）②每个诊断的支持证据与不支持证据 ③鉴别诊断分析 ④建议进一步检查项目 ⑤证据来源引用                                                                   |
| **调用工具列表** | `get_medical_record`（获取病历）、`get_lab_result`（检验报告）、`get_image_report`（影像报告）、`diagnosis_suggestion`（诊断建议）、知识管理智能体 RAG 检索（指南文献） |
| **权限要求**   | 需`patient:read`、`emr:read`、`lab:read`、`imaging:read`权限                                                                       |
| **风险等级**   | medium（诊断建议仅供参考，不替代医生最终诊断）                                                                                                   |
| **协作边界**   | 仅呈现证据、问题和待确认事项，**不做出最终诊断**；所有诊断建议必须经医生确认                                                                                     |
| **协作关系**   | 与 AG-04 检验解读协同，检验异常作为诊断输入；诊断结果供 AG-05 方案生成使用                                                                                 |

#### AG-04：检验检查解读智能体



| 项目         | 内容                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------ |
| **智能体名称**  | 循证检验检查结果分析智能体                                                                                    |
| **职责描述**   | 结合检验检查结果与临床信息，解读异常指标的临床意义，提示可能的疾病方向，给出进一步检查建议                                                    |
| **触发条件**   | ①上传检验 / 检查报告后自动触发；②医生在诊疗对话中提问（如 "帮我看看这个报告"）；③新检验结果到达时主动推送解读                                      |
| **输入**     | ①检验报告（项目 / 结果 / 参考值 / 异常标识）②检查报告（所见 / 结论）③患者临床信息（病史 / 诊断 / 用药）④相关指南                              |
| **输出**     | ①异常指标高亮与解读 ②指标变化趋势分析 ③可能的临床意义 / 疾病方向 ④建议进一步检查或复查 ⑤危急值预警                                          |
| **调用工具列表** | `get_lab_result`（获取检验报告）、`get_image_report`（获取影像报告）、`critical_value_alert`（危急值预警）、知识管理智能体 RAG 检索 |
| **权限要求**   | 需`lab:read`、`imaging:read`、`patient:read`权限                                                      |
| **风险等级**   | medium（解读仅供参考，危急值需立即通知医护人员）                                                                      |
| **协作关系**   | 检验解读结果作为 AG-03 循证诊断的输入；危急值触发 AG-06 风险预警                                                          |

#### AG-05：诊疗方案生成智能体



| 项目         | 内容                                                                                                                                                            |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **智能体名称**  | 循证诊疗方案生成智能体                                                                                                                                                   |
| **职责描述**   | 基于指南、患者情况和医生诊疗思路，生成诊疗方案建议，包含用药指导、适用说明、禁忌、监测与随访注意事项                                                                                                            |
| **触发条件**   | ①诊断明确后医生调用；②自然语言请求（如 "给出治疗方案"）                                                                                                                                |
| **输入**     | ①确定诊断 ②患者基本情况（年龄 / 性别 / 体重 / 肝肾功能 / 过敏史）③合并疾病与用药 ④相关临床指南 ⑤医生的初步方案思路                                                                                           |
| **输出**     | ①诊疗方案建议（药物 / 非药物 / 手术 / 介入）②用药剂量与疗程建议 ③适应症与禁忌症说明 ④不良反应监测要点 ⑤随访计划建议 ⑥指南依据引用                                                                                    |
| **调用工具列表** | `treatment_plan_suggestion`（治疗方案建议）、`drug_interaction_check`（药物相互作用检查）、`get_drug_info`（药品信息查询）、`create_order`（医嘱开具，需医生确认后）、`create_prescription`（处方开具，需医生确认后） |
| **权限要求**   | 需`patient:read`、`order:create`（医嘱开具需执业医师资格）、`prescription:create`（处方权分级校验）                                                                                    |
| **风险等级**   | high（涉及用药安全，必须医生审核确认；处方需双重确认 + 药师审核）                                                                                                                          |
| **协作边界**   | 方案为**建议参考**，必须经医生审核确认后才可执行；不自动开具医嘱 / 处方                                                                                                                       |
| **协作关系**   | 方案中的用药需经 AG-04 检验解读确认肝肾功能；方案生成后触发 AG-11 患者随访计划                                                                                                                |

#### AG-06：风险预警智能体



| 项目         | 内容                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------- |
| **智能体名称**  | 临床风险预警智能体                                                                                                         |
| **职责描述**   | 结合检验指标、病历信息、症状信息和生命体征，实时识别高危患者，辅助医护人员早期发现病情变化和潜在风险                                                                |
| **触发条件**   | ①患者数据更新时自动监测（检验结果到达、生命体征变化）；②医生 / 护士手动查询患者风险；③定时轮询住院患者                                                            |
| **输入**     | ①实时生命体征（心率 / 血压 / 呼吸 / 血氧 / 体温）②检验结果（血常规 / 生化 / 凝血等）③病历信息（诊断 / 病史 / 用药）④症状描述 ⑤预警规则库 / 模型                          |
| **输出**     | ①风险等级评估（低 / 中 / 高 / 危急）②风险因素清单 ③预警原因解释 ④建议干预措施 ⑤预警时间线                                                             |
| **调用工具列表** | `get_lab_result`（检验报告）、`critical_value_alert`（危急值预警）、`get_medical_record`（病历信息）、`get_patient_detail`（患者详情）、消息推送服务 |
| **权限要求**   | 需`patient:read`、`lab:read`、`vitals:read`（生命体征读取）权限；预警推送需`notification:send`权限                                     |
| **风险等级**   | medium（预警为辅助提示，临床干预决策由医护人员做出）                                                                                     |
| **应用场景**   | 住院患者病情恶化预警、急诊分诊风险评估、术后并发症预警、脓毒症 / AKI 等特定风险识别                                                                     |
| **协作关系**   | 危急值来自 AG-04 检验解读；预警结果推送至医生工作台并记录到 AG-20 患者时间线                                                                     |

### 1.4 L2 管理智能体详细设计

#### AG-07：病历质控智能体



| 项目         | 内容                                                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **智能体名称**  | 智能病历质控智能体                                                                                                                           |
| **职责描述**   | 将病历质控前移至临床工作流，针对文书完整性、逻辑一致性及可能存在的风险给出结构化提示，帮助问题在可修正阶段被发现                                                                            |
| **触发条件**   | ①病历生成 / 修改时实时校验；②医生提交病历时全量校验；③质控员批量抽查                                                                                               |
| **输入**     | ①病历文书全文 ②患者基本信息 ③关联的检验检查 / 医嘱数据 ④质控规则库 ⑤病历书写规范                                                                                      |
| **输出**     | ①质控问题清单（按严重程度排序）②问题定位（具体段落 / 字段）③问题描述与依据 ④修改建议 ⑤质控得分                                                                                |
| **调用工具列表** | `medical_record_quality_check`（病历质控）、`get_medical_record`（获取病历）、`get_order_list`（医嘱列表，用于医嘱检测闭环校验）、`get_lab_result`（检验报告，用于跨文书一致性校验） |
| **权限要求**   | 需`emr:read`、`qc:execute`（质控执行）权限；质控结果写入需`qc:write`权限                                                                                |
| **风险等级**   | low（质控为辅助检查，不直接修改病历）                                                                                                                |
| **校验类型**   | ①书写规范性校验 ②医嘱检测闭环校验 ③文书存在性 / 字段一致性校验 ④围手术期要素校验 ⑤跨文书一致性校验                                                                             |

#### AG-08：病种规范质控智能体



| 项目         | 内容                                                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------------- |
| **智能体名称**  | 单病种诊疗规范质控智能体（可配置型）                                                                                                   |
| **职责描述**   | 针对特定病种（如嗜铬细胞瘤 / PPGL）创建专属质控智能体，按照该病种的诊疗规范配置规则库，对该病种患者的全程诊疗进行规范性质控                                                    |
| **触发条件**   | ①患者诊断匹配到质控病种时自动激活；②科室主任 / 质控员创建并配置；③定时批量校验                                                                           |

### 1.7 智能体间协作关系与通信机制

#### 1.7.1 协作模式

智能体间协作采用**三种模式**：



| 协作模式     | 说明                                     | 典型场景                                     | 通信方式                    |
| -------- | -------------------------------------- | ---------------------------------------- | ----------------------- |
| **顺序链式** | 前一个 Agent 的输出作为后一个 Agent 的输入，按固定流程依次执行 | 门诊诊疗：ADS→质控→诊断→方案→随访                     | 同步调用，结果直接传递             |
| **并行协同** | 多个 Agent 同时执行不同子任务，结果聚合后统一呈现           | 复杂病例分析：诊断 Agent + 检验 Agent + 影像 Agent 并行 | 异步并行，Promise.all 聚合     |
| **事件触发** | 一个 Agent 的状态变化触发另一个 Agent 的激活          | 检验危急值→风险预警→推送通知                          | 事件总线（Event Bus），发布 - 订阅 |

#### 1.8.3 结果聚合策略

当多个 Agent 并行执行时，超级调度智能体按以下策略聚合结果：



1. **结构化聚合**：每个 Agent 返回结构化结果（含来源 Agent、置信度、证据引用），调度器按统一模板整合

2. **冲突检测**：若多个 Agent 结论冲突（如诊断建议不一致），标记冲突并呈现全部观点，由医生裁决

3. **优先级排序**：按风险等级和临床相关性排序结果，高风险 / 高相关内容前置

4. **溯源保留**：聚合结果保留每个子结论的来源 Agent 和证据引用，支持点击溯源

5. **摘要生成**：对多 Agent 结果生成统一摘要，同时保留各 Agent 详细结果供展开查看

## 3. 医疗工具框架设计

### 3.1 设计目标与原则

医疗工具框架基于 claude-code 的`buildTool()`工厂模式（`Tool.ts:783`）扩展，核心设计目标：



1. **安全优先**：所有工具默认 fail-closed，风险等级明确，高风险操作强制确认

2. **合规可审计**：每次工具调用记录完整审计日志，符合医疗行业监管要求

3. **领域标准化**：工具接口符合 HL7 FHIR 等医疗标准，便于系统集成

4. **可扩展**：新工具开发遵循统一规范，支持医院自定义工具

5. **性能可控**：工具执行支持超时控制、并发限制、结果缓存

### 3.5 工具并发执行策略

#### 3.5.1 医疗场景并发规则

基于 claude-code 的`partitionToolCalls()`（`toolOrchestration.ts:91`）并发 / 串行分区机制，医疗场景的并发规则：



| 并发安全性    | 判定条件                                 | 典型工具                                                                                         | 执行方式                            |
| -------- | ------------------------------------ | -------------------------------------------------------------------------------------------- | ------------------------------- |
| **可并发**  | 只读工具 + low 风险 + 无副作用 + 不依赖其他工具结果     | query\_patient、get\_lab\_result、get\_image\_report、get\_drug\_info、get\_medical\_template    | 并发组，最大并发 10                     |
| **条件并发** | 只读工具但需患者上下文一致                        | get\_medical\_record（同一患者可并发，不同患者串行）                                                         | 按患者 ID 分组并发                     |
| **必须串行** | 写入工具 /medium 及以上风险 / 有副作用 / 依赖前置工具结果 | write\_progress\_note、create\_order、create\_prescription、update\_patient\_info、cancel\_order | 严格串行，前一个的 contextModifier 影响后一个 |

#### 3.5.2 并发执行流程图



```
LLM返回多个tool\_use blocks

&#x20;   │

&#x20;   ▼

partitionToolCalls() 【按isConcurrencySafe分区】

&#x20;   │

&#x20;   ▼

medicalRiskPartition() 【按风险等级二次分区】

&#x20;   │

&#x20;   ├─ 并发组：\[get\_lab\_result, get\_image\_report, get\_drug\_info]

&#x20;   │   └─ runToolsConcurrently()

&#x20;   │       ├─ 并行执行（Promise.all，最大并发10）

&#x20;   │       └─ 收集全部结果后统一返回

&#x20;   │

&#x20;   ├─ 串行组1：\[write\_progress\_note]

&#x20;   │   └─ runToolsSerially()

&#x20;   │       ├─ 执行
```

#### 3.5.3 StreamingToolExecutor 医疗适配

claude-code 的`StreamingToolExecutor`实现工具执行与 API 流式接收并行。医疗场景适配：



1. **注册阶段**：tool\_use 块到达时立即注册，同时进行风险等级预判定

2. **执行阶段**：low 风险工具立即后台执行；medium/high 风险工具等待确认后执行

3. **收集阶段**：工具结果返回时先脱敏再加入结果集

4. **阻塞处理**：若存在 high 风险工具待确认，API 流结束后暂停循环，等待确认结果

## 5. 子代理（科室代理）设计

### 5.1 设计思路

基于 claude-code 的 AgentTool 子代理系统（`src/tools/AgentTool/`），健澜医疗 Agent 的子代理定位为**科室专属代理**—— 每个临床科室拥有独立的子代理，具备该科室的专用工具集、专业知识库、专科系统提示词和权限范围。

科室子代理与主代理（超级调度 AG-18）的关系：



* 主代理负责意图识别和任务分发

* 科室子代理负责专科深度推理和工具执行

* 子代理执行结果返回主代理进行聚合和呈现

### 5.2 基于 AgentTool 的改造点

claude-code 的 AgentTool（`AgentTool.tsx`，233KB）提供了完整的子代理框架，医疗化改造点：



| 原机制                                | 医疗化改造                             | 对应文件                                                  |
| ---------------------------------- | --------------------------------- | ----------------------------------------------------- |
| `builtInAgents.ts` 内置代理定义          | 新增 8 类科室代理定义                      | `src/medical-tools/agents/builtInDepartmentAgents.ts` |
| `loadAgentsDir.ts` 目录加载            | 支持从医院配置目录加载自定义科室代理                | `src/medical-tools/agents/loadDepartmentAgents.ts`    |
| `forkSubagent.ts` 上下文创建            | 扩展 MedicalToolUseContext，注入科室专属配置 | `src/medical-tools/agents/forkDepartmentAgent.ts`     |
| `runAgent.ts` 子代理执行                | 增加医疗超时处理、急诊优先级、结果审核               | `src/medical-tools/agents/runDepartmentAgent.ts`      |
| `agentMemory.ts` 代理记忆              | 科室级共享记忆（诊疗经验、罕见病例）                | `src/medical-tools/agents/departmentMemory.ts`        |
| 工具过滤 `resolveAgentTools`           | 按科室权限过滤工具集                        | 复用原机制，配置医疗工具白名单                                       |
| 独立转录 `setAgentTranscriptSubdir`    | 子代理转录关联患者 ID，符合病历管理规定             | 扩展原机制                                                 |
| MCP 隔离 `initializeAgentMcpServers` | 科室专属 MCP 服务器（如心内科专属监护系统）          | 配置化                                                   |

## 6. 技能系统设计

### 6.1 设计思路

基于 claude-code 的技能系统（`src/skills/`），健澜医疗技能系统定位为**临床路径技能库**—— 将临床诊疗指南、操作规范、质控标准等转化为可执行的 AI 技能，供各 Agent 在诊疗过程中调用。

claude-code 技能系统核心机制可直接复用：



* 目录 + SKILL.md 格式定义（`loadSkillsDir.ts`）

* 多级加载源（managed/user/project/additional）

* 条件技能激活（paths frontmatter）

* 动态发现（文件路径触发）

* SkillTool 执行（参数替换、内联 Shell、fork 执行）

医疗化改造重点：技能内容全面临床路径化，加载源增加医院 / 科室级，执行增加医疗安全校验。

```
\# 急性胸痛诊疗路径

\## 第一步：快速评估（0-10分钟）

1\. 立即评估生命体征（心率、血压、呼吸、血氧、意识）

2\. 完成12导联心电图（目标10分钟内）

3\. 采集胸痛特征：部位、性质、持续时间、诱发因素、缓解因素、放射痛

4\. 识别高危征象：

&#x20;  \- 持续胸痛>20分钟

&#x20;  \- 心电图ST段抬高/压低

&#x20;  \- 血流动力学不稳定

&#x20;  \- 意识障碍

\## 第二步：鉴别诊断

按可能性排序：

1\. \*\*急性冠脉综合征（ACS）\*\*：压榨性胸痛，向左肩/下颌放射，含服硝酸甘油可缓解

2\. \*\*主动脉夹层\*\*：撕裂样胸痛，向后背放射，双上肢血压差异>20mmHg

3\. \*\*肺栓塞\*\*：突发呼吸困难+胸痛，D-二聚体升高
```

```
\# 社区获得性肺炎诊疗路径

\## 诊断标准

1\. 社区发病

2\. 肺炎相关临床表现：新发咳嗽咳痰/呼吸困难/发热/肺部啰音

3\. 影像学检查：新发斑片状浸润影/间质性改变

4\. 排除肺结核、肺癌、肺水肿等其他疾病

\## 严重程度评估（CURB-65评分）

\- 意识障碍（Confusion）：1分

\- 尿素氮>7mmol/L（Urea）：1分

\- 呼吸频率≥30次/分（Respiratory）：1分

\- 收缩压<90mmHg或舒张压≤60mmHg（Blood pressure）：1分

\- 年龄≥65岁：1分

\- 0-1分：门诊治疗

\- 2分：住院治疗

\- ≥3分：ICU评估

\## 抗感染治疗

\### 门诊患者

\- 无基础疾病：阿莫西林/多西环素/大环内酯类

\- 有基础疾病或近3月使用抗生素：β-内酰胺类+大环内酯类，或呼吸喹诺酮类

\### 住院患者

\- 非ICU：β-内酰胺类+大环内酯类，或呼吸喹诺酮类

\- ICU：β-内酰胺类+大环内酯类（铜绿假单胞菌风险用抗假单胞菌β-内酰胺类）

\## 随访

\- 初始治疗72小时后评估疗效

\- 体温正常、症状改善可序贯口服

\- 疗程一般5-7天，非典型病原体10-14天
```

#### 7.4.2 权限安全审查



* [ ] Agent 定义了明确的 requiredPermissions

* [ ] 高风险工具（create\_order/create\_prescription）配置了双重确认

* [ ] 处方权分级校验（普通 / 特殊 / 麻醉）

* [ ] 跨科室患者访问需授权

* [ ] 急诊越权操作需事后审计

* [ ] 子代理工具集过滤正确（无越权工具）

* [ ] 技能执行权限与 Agent 权限一致

#### 7.4.3 医疗安全审查



* [ ] 系统提示词包含 "AI 不替代医生决策" 声明

* [ ] 诊断建议标注可能性和不确定性

* [ ] 治疗方案标注 "仅供参考，请医生确认"

* [ ] 药品剂量标注 "剂量仅供参考，请根据患者情况调整"

* [ ] 危急值识别逻辑经过验证

* [ ] 药物相互作用检查覆盖所有处方

* [ ] 禁忌症筛查覆盖所有用药建议

* [ ] 高风险操作有明确的人工确认环节

* [ ] Agent 不会自动执行医嘱 / 处方

* [ ] 异常 / 不确定情况会升级给人工

#### 7.4.4 审计合规审查



* [ ] 所有工具调用记录审计日志

* [ ] 审计日志包含：时间、用户、角色、患者 ID、工具名、输入摘要、输出摘要、IP

* [ ] 审计日志不可篡改（WORM 存储）

* [ ] 审计日志保留≥6 个月

* [ ] 高风险操作记录完整确认链（操作人 + 确认人 + 时间）

* [ ] Agent 决策过程可追溯（关键决策点记录）

* [ ] 技能使用记录可追溯

* [ ] 子代理转录可审计

#### 7.4.5 系统安全审查



* [ ] 外部系统接口有超时和重试机制

* [ ] 外部系统不可用时 Agent 有降级策略

* [ ] 输入参数 Zod schema 校验完整

* [ ] 输出 schema 校验防止异常数据

* [ ] 防止 Prompt Injection（系统提示词隔离）

* [ ] 防止工具参数注入（参数白名单校验）

* [ ] 并发控制正确（写操作串行）

* [ ] 内存泄漏检测通过

* [ ] 依赖组件无已知高危漏洞
