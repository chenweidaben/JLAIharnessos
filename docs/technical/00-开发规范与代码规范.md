## 1. 项目概述

### 1.1 项目背景
本项目基于 claude-code 2.1.88 开源架构（source map 还原版），定制开发为健澜科技数智医院智能体应用。核心 Agent 框架复用，工具集、技能、UI、知识库全面医疗化定制。

### 1.2 技术栈
- **运行时**：Bun >= 1.3.0
- **语言**：TypeScript 6.0+（严格模式）
- **UI框架**：React 19 + Ink 6.8（终端渲染）
- **状态管理**：React Hooks + 自定义状态管理
- **API客户端**：@anthropic-ai/sdk 0.80.0
- **协议**：MCP (Model Context Protocol) 1.29.0
- **构建工具**：Bun build (build.ts)
- **包管理**：pnpm（兼容bun）

### 1.3 代码来源说明
- 基础架构源自 `C:\claudecode5.1.118\claude-code-source\`
- 所有复用代码需保留原始版权声明
- 定制开发代码归健澜科技所有

## 3. 命名规范

### 3.1 文件命名
- **组件文件**：PascalCase，如 `PatientCard.tsx`
- **工具/服务文件**：camelCase，如 `patientService.ts`
- **类型定义文件**：PascalCase，如 `MedicalTypes.ts`
- **常量文件**：UPPER_SNAKE_CASE，如 `MEDICAL_CONSTANTS.ts`
- **测试文件**：与源文件同名加 `.test`，如 `patientService.test.ts`
- **索引文件**：`index.ts`

### 3.2 代码命名
| 类型 | 规范 | 示例 |
|------|------|------|
| 类/组件/类型 | PascalCase | `PatientQueryTool`, `MedicalRecord` |
| 函数/方法/变量 | camelCase | `getPatientInfo()`, `patientId` |
| 常量 | UPPER_SNAKE_CASE | `MAX_CONTEXT_TOKENS` |
| 接口 | PascalCase（I前缀可选） | `IToolDefinition`, `ToolDefinition` |
| 枚举 | PascalCase | `PatientStatus` |
| 布尔变量 | is/has/can 前缀 | `isAuthenticated`, `hasPermission` |
| 异步函数 | 动词开头 | `fetchPatient()`, `saveRecord()` |

### 3.3 医疗术语规范
- 公司名称：**健澜科技**（严禁使用"建兰"等同音字）
- 产品名称：健澜科技数智医院智能体
- 医疗术语使用标准中文医学术语，英文缩写首次出现需注明全称
- 药品名称使用通用名，不使用商品名

## 4. 代码风格规范

### 4.1 TypeScript 严格模式
```typescript
// 必须开启严格模式
"strict": true

// 禁止使用 any，必须使用 unknown 或具体类型
// ❌ 禁止
function process(data: any) { ... }

// ✅ 推荐
function process(data: unknown) {
  if (isMedicalRecord(data)) { ... }
}

// 必须显式声明函数返回类型
// ❌ 禁止
export function getPatient(id) { ... }

// ✅ 推荐
export function getPatient(id: string): Promise<Patient> { ... }
```

### 4.2 导入规范
```typescript
// 按以下顺序分组，组间空行分隔
// 1. 外部依赖
import React from 'react';
import { Box, Text } from 'ink';

// 2. 内部模块（使用路径别名）
import { AgentLoop } from '@core/agent/AgentLoop';
import { PatientTool } from '@medical/patient/PatientTool';

// 3. 类型导入
import type { Patient, MedicalRecord } from '@/types/medical';

// 4. 样式/常量
import { THEME } from '@ui/theme';
```

### 4.3 错误处理
```typescript
// 所有异步操作必须有错误处理
// ✅ 推荐
try {
  const patient = await patientService.getById(id);
  return patient;
} catch (error) {
  logger.error('获取患者信息失败', { patientId: id, error });
  throw new MedicalAgentError('PATIENT_NOT_FOUND', '患者信息获取失败');
}

// 自定义错误类必须包含错误码
class MedicalAgentError extends Error {
  constructor(
    public code: string,
    message: string,
    public details?: Record<string, unknown>
  ) {
    super(message);
    this.name = 'MedicalAgentError';
  }
}
```

### 4.4 异步编程
```typescript
// 使用 async/await，禁止回调地狱
// 并行操作使用 Promise.all
const [patient, records, orders] = await Promise.all([
  patientService.getById(id),
  emrService.getByPatient(id),
  orderService.getByPatient(id),

// 超时控制
const result = await Promise.race([

  ),
```

## 5. Agent 工具开发规范

### 5.1 工具定义格式
```typescript
// 每个医疗工具必须遵循此格式
import { z } from 'zod';
import type { ToolDefinition, ToolContext } from '@core/tools/types';

export const queryPatientTool: ToolDefinition = {
  name: 'query_patient',
  description: '根据患者ID或姓名查询患者基本信息',
  category: 'patient',
  riskLevel: 'low', // low | medium | high
  requiresAuth: true,
  requiresConfirm: false,
  inputSchema: z.object({
    patientId: z.string().optional().describe('患者唯一ID'),
    name: z.string().optional().describe('患者姓名'),
    idCard: z.string().optional().describe('身份证号'),
  }),
  outputSchema: z.object({
    success: z.boolean(),
    data: z.array(patientSchema),
    total: z.number(),
  }),
  async execute(input: unknown, context: ToolContext): Promise<unknown> {
    // 1. 参数校验（由框架自动完成）
    // 2. 权限检查
    if (!context.user.permissions.includes('patient:read')) {
      throw new MedicalAgentError('PERMISSION_DENIED', '无患者查询权限');
    }
    // 3. 审计日志
    context.audit.log('query_patient', { input, userId: context.user.id });
    // 4. 执行查询
    const result = await patientService.query(input);
    // 5. 数据脱敏
    return desensitizePatientData(result);
  },
};
```

### 5.2 工具分类
| 分类 | 前缀 | 风险等级 | 示例 |
|------|------|----------|------|
| 患者管理 | patient_ | low | query_patient, update_patient |
| 电子病历 | emr_ | medium | get_medical_record, write_progress_note |
| 医嘱管理 | order_ | high | create_order, cancel_order |
| 处方管理 | prescription_ | high | create_prescription, check_drug_interaction |
| 检验检查 | lab_ | low/medium | get_lab_result, order_lab_test |
| 影像检查 | imaging_ | medium | get_image_report, view_dicom |
| 临床决策 | cds_ | medium | drug_interaction_check, diagnosis_suggestion |
| 系统集成 | integration_ | medium | sync_to_his, fetch_from_lis |

### 5.3 风险等级与确认机制
- **low**：只读查询，无需确认
- **medium**：数据修改/创建，需用户确认
- **high**：涉及医嘱/处方/用药安全，需双重确认+药师审核

## 6. 安全合规规范

### 6.1 数据脱敏
```typescript
// 所有患者敏感数据在输出到LLM前必须脱敏
const SENSITIVE_FIELDS = ['idCard', 'phone', 'address', 'emergencyContact'];

function desensitize(data: Record<string, unknown>): Record<string, unknown> {
  const result = { ...data };
  for (const field of SENSITIVE_FIELDS) {
    if (result[field]) {
      result[field] = maskSensitive(String(result[field]));
    }
  }
  return result;
}

// 身份证：110***********1234
// 手机号：138****5678
```

### 6.2 审计日志
- 所有工具调用必须记录审计日志
- 日志内容：时间、用户ID、角色、工具名、输入参数（脱敏后）、输出摘要、IP地址
- 日志保留期：不少于6个月
- 日志不可篡改

### 6.3 权限控制
```typescript
// 基于RBAC的权限模型
interface User {
  id: string;
  name: string;
  role: 'doctor' | 'nurse' | 'pharmacist' | 'admin' | 'patient';
  department: string;
  permissions: string[];
  title?: string; // 职称：主任医师/副主任医师/主治医师/住院医师
}

// 权限粒度：模块:操作
// 示例：patient:read, order:create, prescription:audit
```

## 7. Git 工作流规范

### 7.1 分支策略
- `main`：生产分支，受保护，仅通过PR合并
- `develop`：开发分支，日常集成
- `feature/*`：功能分支，如 `feature/patient-query-tool`
- `fix/*`：修复分支，如 `fix/drug-interaction-bug`
- `release/*`：发布分支，如 `release/v0.2.0`

### 7.2 提交信息格式
```
<type>(<scope>): <subject>

<body>

<footer>
```

**type 类型**：
- `feat`：新功能
- `fix`：修复
- `docs`：文档
- `style`：代码格式
- `refactor`：重构
- `test`：测试
- `chore`：构建/工具

**示例**：
```
feat(medical-tools): 新增患者查询工具

- 支持按患者ID/姓名/身份证查询
- 集成HIS系统适配器
- 实现数据脱敏与审计日志

Closes #123
```

### 7.3 代码审查
- 所有PR必须至少1人审查通过
- 核心引擎/安全模块需2人审查
- 审查清单：功能正确性、安全性、性能、代码规范、测试覆盖

## 9. 性能规范

### 9.1 响应时间要求
- 工具调用响应时间 < 2秒（P95）
- LLM首token响应 < 3秒
- 上下文压缩 < 1秒
- 知识库检索 < 500ms

### 9.2 资源限制
- 单会话内存占用 < 512MB
- 并发会话数根据服务器配置动态调整
- 大文件处理必须流式处理，禁止全量加载
