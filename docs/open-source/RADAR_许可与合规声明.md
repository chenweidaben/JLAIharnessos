### 1.1 为什么「代码开源」不等于「可商用 AI 模型」

- Apache-2.0 只覆盖**代码**；
- 权重是独立分发的数据/模型资产，采用 **CC BY-NC-SA 4.0**，其中 **NC（NonCommercial）** 明确排除商业使用；
- 因此：你可以合法地**阅读、修改、商用健澜与上游的代码**，但**不能直接把这份预训练权重用于商业目的**，除非取得另行授权。

### 1.2 商用授权路径

如需在**商业产品 / 盈利性院内服务**中使用该预训练权重，须：

1. 联系 DAMO-RADAR 权重版权方（论文/模型卡对应机构），就 CC BY-NC-SA 4.0 的 NC 条款取得**商业授权**；

## 2. 第二阅片定位与医疗器械合规

### 2.1 产品定位

DAMO-RADAR 在本系统中被严格定位为**第二阅片（second reader）/ 辅助决策（decision support）**：

- 输出为**概率与结构化发现**，**不构成自动诊断**；
- 所有 AI 报告必须经**放射科医师复核签名**（`POST /imaging/ai/jobs/:id/review`）后方可进入正式报告；
- 系统在 UI 与 `RadarResult.disclaimer` 中固定展示免责声明，禁止把 AI 输出当作终稿。

### 2.2 院内验证（必须前置）

任何真实病例上线前，部署方应完成：

- **本机构数据验证**：在本院既往腹部增强 CT 与金标准报告上，按 findings 级别评估敏感度/特异度/AUC（方法见训练微调复现指南）；
- **阈值本地化**：`RADAR_POSITIVE_THRESHOLD`、`RADAR_MAJOR_THRESHOLD`、`RADAR_CRITICAL_FINDINGS` 按本院读片习惯调参并留痕；
- **流程验证**：医师签名闭环、critical 危急值推送、误报/漏报处理 SOP 走通；
- **漂移监控**：上线后持续监控输入分布与输出分布漂移。

### 2.3 医疗器械合规说明

- 本交付为**软件集成与工程框架**，不代替任何医疗器械注册证；
- 若在目标国家/地区将其作为**医疗器械**上市，须由责任主体按当地法规（如中国 NMPA 人工智能医疗器械软件审评、美国 FDA、欧盟 MDR/AI Act 等）完成注册/备案、临床评价与质量体系核查；
- 「第二阅片、人工复核、不自动诊断」的设计是降低监管风险的重要前提，但**不等于**已获医疗器械认证；具体分类与路径须由注册专员结合目标市场判断。

## 3. 数据隐私与安全边界

| 要求 | 本融合的落实 |
|------|--------------|
| 脱敏 | DICOM→NIfTI 转换在集成层去除/隔离患者身份字段，Python 服务只见 `study_uid` 与 `file_ref`，不见姓名/ID 明文 |
| 日志脱敏 | `logging_redact.py` 保证日志中不打印 PHI；失败响应只回结构化错误体 + traceId，绝不泄露堆栈/SQL/路径 |
| 审计 | 复核签名写入审计（哈希链防篡改），持久化 `data/imaging-ai-jobs.json`；重复提交禁用 |
| 权重与数据不回传 | 权重**不入库、不随镜像分发**；推理为**院内本地运行**，不上传 DICOM/大数据到外部；离线部署见部署手册 |
| 网络收敛 | 推理端口 8090 仅内网/回环，业务端点需 `X-Internal-Token`；公网只暴露 BFF 8080 |

> 患者数据的收集、存储、共享与跨境，仍须遵守《个人信息保护法》《数据安全法》《医疗卫生机构网络安全管理办法》及等保要求；本融合默认「数据不出院」，但具体合规责任在部署方。
